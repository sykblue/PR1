# 계정과 사진 DB

사용자 요청: 아이디·비밀번호와 실제 사진 파일·사진 정보를 계정별 DB에 저장한다. 기본 DB는 `data/hairline.sqlite3`이며 `.env`의 `DATABASE_PATH`로 위치를 바꿀 수 있다. 별도 DB 서버 설치는 필요하지 않다.

## 저장 내용

| 테이블 | 내용 |
| --- | --- |
| `users` | 계정 ID, 정규화한 아이디, scrypt 비밀번호 해시, 가입일. 비밀번호 원문은 저장하지 않는다. |
| `sessions` | 세션 토큰 해시, 계정 ID, 만료 시각. 기존 로그인·폐기·CSRF 검증을 사용한다. |
| `analysis_history` | 계정 ID, 생성 시각, 사용 모델, 요약, 리포트 JSON. |
| `photos` | 무작위 사진 ID, 계정 ID, 용도, 기존 학습 ID/리포트 연결, 저장 시각, JPEG BLOB, 가로·세로, 바이트 수, MIME, SHA-256, 학습 라벨·그룹·특징값/관찰 정답 JSON. |

사진에는 원본 파일명과 EXIF/GPS를 저장하지 않는다. 업로드의 방향을 반영하고 메타데이터를 제거한 사진을 사용한다. `photos`는 계정·용도·원본 레코드 ID의 조합으로 중복 등록을 막는다. 용도는 `analysis`, `local_training`, `vision_training`이다. 공통 확대 두피 모델의 16,298장 자료는 사용자 계정의 사진으로 등록하지 않는다.

## 사용 방법

- 회원가입을 완료하면 아이디와 비밀번호 해시가 기존 `users`에 저장된다. 재시작 후에도 로그인할 수 있으며 응답에는 비밀번호 해시를 포함하지 않는다.
- 분석 화면의 **분석 리포트를 내 계정에 저장해요**와 **이 사진도 내 계정에 함께 저장해요**를 함께 선택하면 분석 성공 후 리포트와 사진을 하나의 SQL 트랜잭션으로 저장한다. 사진 선택은 기본 꺼짐이고 새 사진·계정 변경·리포트 저장 해제 시 초기화된다. 사진 저장만 선택한 API 요청은 거절한다.
- 내 기록에서 해당 리포트를 다시 열면 함께 저장한 사진을 표시한다. 새 분석에는 사진을 다시 선택한다. 사진을 저장하지 않았던 이전 리포트에는 사진이 없다는 안내를 표시한다.
- 로컬 학습·비전 학습은 기존 학습 저장 동의와 등록/삭제 화면을 사용한다. 등록 시 사진 파일과 정보도 DB에 저장하고 라벨·정답 수정도 반영한다. JSON·JPEG 파일은 기존 학습 코드와 GPU 작업의 입력으로 보존한다.
- 리포트 삭제는 연결한 분석 사진을 DB 외래 키로 함께 삭제한다. 학습 사진 삭제는 작업용 JPEG·목록과 DB 레코드를 함께 갱신한다. SQL/목록 저장이 실패하면 이전 목록과 사진을 복구한다.

## 조회 API와 접근

| API | 응답 |
| --- | --- |
| `GET /api/photos` | 로그인한 계정의 최근 사진 최대 500개 정보. 이미지 BLOB·특징값·내부 경로는 목록에 포함하지 않는다. |
| `GET /api/photos/<사진 ID>` | 본인 사진의 정보·인증이 필요한 이미지 URL. |
| `GET /api/photos/<사진 ID>/image` | 본인 사진의 JPEG. `Cache-Control: no-store`, 로그인 필수. |
| `GET /api/history/<리포트 ID>` | 기존 결과와 선택 저장한 `photo` 정보. 이미지 자체를 JSON/base64에 넣지 않는다. |
| `POST /api/analyze` | 기존 필드 외에 `save_photo=true`. `save_history=true`·로그인·전송 동의가 필요하다. |

사용자가 보낸 계정 ID로 사진을 선택하지 않는다. 서버 세션의 계정 ID와 사진 ID를 함께 조회하며 다른 계정의 사진은 404, 비로그인은 401을 반환한다. 사진·DB는 정적 파일로 제공하지 않는다. `GET /api/status`의 `photo_storage=sqlite`, `analysis_photo_storage_opt_in=true`로 저장 방식을 확인한다.

## 기존 자료와 백업

기존 DB는 테이블을 지우지 않고 `photos`와 인덱스를 추가한다. 기존 계정별 학습 목록이 있으면 시작 시 이미 저장에 동의한 JPEG·레코드를 DB에 등록한다. 두 번 실행해도 사진 ID·개수가 유지된다. 기존 아이디·비밀번호 해시·세션·리포트·학습 파일·모델은 덮어쓰지 않는다. 이전 분석에서 저장하지 않았던 사진은 복원하지 않는다.

실제 적용 전 기존 SQLite를 `.cache`에 백업한다. 운영 중 복사에는 SQLite backup API를 사용하고, 일반 파일 복사는 서버 종료 후 수행한다. 전체 복구에는 DB와 세션 서명 키, 기존 학습 폴더의 목록·모델 파일도 함께 보관한다. DB에는 실제 사진과 계정 정보가 포함되므로 웹 정적 폴더나 Git에 넣지 않는다.

## 검증 범위

임시 SQLite와 합성 사진으로 계정 간 조회 차단·별도 저장 선택·EXIF 제거·재시작 유지·삭제 연동·SQL 실패 시 복구·기존 스키마의 반복 마이그레이션을 확인한다. 외부 AI는 모의 응답을 사용하며 테스트용 계정과 사진을 실제 사용자 DB에 만들지 않는다. 브라우저 쪽은 사진 저장 선택의 초기화, 인증된 로컬 이미지 URL만 사용, 계정 변경 시 미리보기 제거를 검증한다.

2026-11-02 전체 Python 202개·Node 139개, 총 341개가 통과했다. 마지막 임시 파일 정리 변경 후 사진 DB 8개·로컬 학습 28개도 다시 통과했다. HTML ID·ARIA·레이블과 JS 구문을 검사했다. 실제 브라우저 렌더링은 별도로 확인하지 않았다.

실제 적용 전 SQLite backup API로 `.cache/before-photo-db-20261102-150546.sqlite3`에 백업했다. 기존 계정 1개·세션 1개·리포트 26개의 내용과 기존 학습 파일 전체의 해시가 유지되는 것을 확인했고, 기존 학습 사진 4장과 정보를 DB에 추가했다. DB의 JPEG 바이트·SHA-256·용량이 기존 파일과 모두 같으며 `quick_check`·외래 키 검사가 통과했다. 최신 로컬 서버를 실행해 저장 옵션 표시·SQLite 저장 상태·사진 API의 비로그인 401과 DB 파일 URL의 404를 확인했다. 기존 확대 두피 참고 모델도 준비 상태를 유지한다.
