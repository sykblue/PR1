# 이전 공통 디자인 기준

이 문서는 개편 이전의 이력이다. 현재 작업에는 [현행 디자인 기준](../../디자인.md)을 적용한다.

개발자 직군의 1차 개인 프로젝트에 적용할 화면 설계·구현 기준이다. 사용자 제공 자료인 **「원티드 (Wanted) — design.md」**를 바탕으로, 5일 안에 구현하고 검증할 수 있는 공통 규칙을 정한다. 개발·데이터·API·제출 기준은 [스킬 규칙.md](<./스킬 규칙.md>)를 함께 따른다.

현재 서비스는 **Hairline Lab**이다. 사진에서 헤어라인·두피 노출을 관찰하고 가상의 모발 변화를 비교한다. 원티드의 시각적 특징을 활용하되 채용 서비스의 기능·문구·브랜드 자산을 가져오지 않는다. 분석은 의료 진단과 구분하고, 가상 편집은 실제 진행 예측으로 표현하지 않는다.

## 1. 디자인 방향

- **밝고 정돈된 화면:** 흰 바탕과 차가운 중성색으로 정보의 구조를 만든다.
- **하나의 강조색:** 주요 실행 버튼, 링크, 포커스에는 파란색을 일관되게 사용한다.
- **타이포그래피 중심의 위계:** 제목 크기, 굵기, 간격으로 중요한 정보를 구분한다.
- **평면과 얇은 테두리:** 카드는 기본적으로 그림자 없이 1px 테두리로 구분한다.
- **충분한 여백:** 입력, 실행, 결과가 구분되고 다음 행동을 쉽게 찾을 수 있게 한다.
- **설명 가능한 상태:** 로딩, 실패, 빈 결과에서도 현재 상황과 다음 행동을 보여 준다.

## 2. 참고 자료의 적용 기준

제공 자료에는 관찰값, 공식 값으로 소개된 값, 합성값과 정정 사항이 함께 있다. 이 문서에서 채택한 값은 프로젝트의 구현 기준이며, 원티드의 현행 공식 규격 전체를 재검증한 것은 아니다.

| 항목 | 이 프로젝트에서 적용할 기준 |
|---|---|
| 테마 | 라이트 테마 우선. 다크 테마는 필요할 때 별도 검증 후 추가 |
| 색상 | 브랜드 파랑은 자료의 HEX `#0066FF` 채택. 아래 CSS 토큰을 프로젝트 기준으로 사용 |
| 중성색 | 자료에 제시된 HEX 앵커를 활용하고 본문·보조 글자의 가독성을 확보 |
| 상태색 | 자료의 밝은 상태색은 아이콘·배경에 활용. 작은 오류 글자는 더 어두운 프로젝트 색상 사용 |
| 반응형 | 자료의 정정된 5단 기준 `0 / 768 / 992 / 1200 / 1600px` 채택 |
| 간격 | 4px 배수 우선. 6·10·14px 등은 컴포넌트 보정에 허용 |
| 라운드·그림자·모션 | 아래에 정한 프로젝트 로컬 규칙으로 관리 |
| 글꼴 | 본문은 Pretendard 계열. Wanted Sans는 필요한 제목에 선택 적용 |

자료의 HEX와 OKLCH를 같은 색으로 가정해 섞지 않는다. 색 공간을 변환해야 하면 도구로 계산하고 실제 배경 위에서 확인한다. 공식 패키지를 직접 도입할 경우에는 패키지의 버전과 실제 토큰 이름을 확인해 역할별로 연결한다.

## 3. 색상 토큰

아래는 HTML·CSS 구현 시 사용할 기준 예시다. 의미가 있는 토큰 이름을 사용하고 화면마다 비슷한 색을 새로 만들지 않는다. 보조 글자와 입력 테두리, 오류 글자에는 가독성을 위한 프로젝트 조정값을 적용했다.

```css
:root {
  color-scheme: light;

  --bg-canvas: #ffffff;
  --bg-surface: #ffffff;
  --bg-subtle: #f7f7f8;
  --bg-muted: #f2f2f4;
  --bg-brand-subtle: #edf4ff;

  --brand-primary: #0066ff;
  --fg-on-brand: #ffffff;
  --fg-strong: #171719;
  --fg-default: #2e2f33;
  --fg-secondary: #646770;
  --fg-placeholder: #70737c;
  --fg-disabled: rgb(55 56 60 / 28%);

  --border-subtle: rgb(112 115 124 / 8%);
  --border-default: rgb(112 115 124 / 22%);
  --border-control: #8a8d96;
  --border-focus: var(--brand-primary);

  --status-danger: #ff4242;
  --status-success: #00bf40;
  --status-warning: #ff9200;
  --surface-danger: rgb(255 66 66 / 8%);
  --surface-success: rgb(0 191 64 / 8%);
  --surface-warning: rgb(255 146 0 / 8%);
  --fg-error: #c62828;

  --interaction-hover: rgb(23 23 25 / 7.5%);
  --interaction-active: rgb(23 23 25 / 18%);
  --focus-ring: 0 0 0 3px rgb(0 102 255 / 20%);

  --radius-sm: 8px;
  --radius-md: 12px;
  --radius-card: 16px;
  --radius-pill: 9999px;
  --shadow-overlay: 0 8px 24px rgb(0 0 0 / 12%);
}
```

- `--brand-primary`는 주요 행동과 링크에 사용한다. 화면 전체를 파란색으로 채우지 않는다.
- 본문과 필수 안내는 `--fg-default`, 보조 정보는 `--fg-secondary`를 사용한다.
- `--fg-placeholder`는 입력 예시에만 사용하며 레이블과 필수 설명을 대체하지 않는다.
- 일반 카드·구분선에는 `--border-subtle`, 입력처럼 조작 경계를 알아야 하는 요소에는 `--border-control`을 사용한다.
- 오류 설명은 `--fg-error`를 사용한다. 성공·경고 설명은 중성색 본문에 상태 이름과 아이콘을 더한다.
- 상태색 아이콘과 배지 배경은 글자 설명을 보완한다. 색만 보고 성공·실패를 판단하게 하지 않는다.
- 차트의 파랑은 핵심 계열에 사용한다. 여러 계열이 필요하면 구분 가능한 색과 범례·직접 레이블을 함께 제공한다.
- 그라디언트는 기본 화면에 사용하지 않는다. 필요한 마케팅 배너나 별도 장식 영역에서만 선택적으로 적용한다.

## 4. 타이포그래피와 문구

기본 폰트 스택:

```css
font-family: "Pretendard JP", "Pretendard Variable", Pretendard,
  -apple-system, BlinkMacSystemFont, system-ui, "Apple SD Gothic Neo",
  "Noto Sans KR", "Malgun Gothic", sans-serif;
```

Wanted Sans를 사용하면 제목에 선택적으로 적용한다. 외부 폰트 로딩이 실패해도 시스템 글꼴로 읽을 수 있어야 한다. 개발 로그·코드처럼 고정폭이 필요한 정보는 시스템 monospace 계열을 사용한다.

다음은 제공 자료에서 필요한 스타일만 골라 정리한 기준이다. 행간은 px 기준으로 관리한다.

| 용도 | 크기 / 행간 | 굵기 | 자간 |
|---|---|---|---|
| 큰 소개 제목, 선택 사항 | 40 / 52px | 700 | -0.0282em |
| 페이지 제목 | 32 / 44px | 700 | -0.0253em |
| 섹션 제목 | 24 / 32px | 700 | -0.023em |
| 하위 제목 | 20 / 28px | 700 | -0.012em |
| 카드 제목 | 18 / 26px | 600 | -0.002em |
| 작은 제목 | 17 / 24px | 600 | 0 |
| 기본 본문 | 16 / 24px | 500 | 0.0057em |
| 긴 설명 | 16 / 26px | 500 | 0.0057em |
| 레이블 | 14 / 20px | 500 | 0.0145em |
| 도움말·메타 정보 | 13 / 18px | 500 | 0.0194em |

- 작은 화면에서는 페이지 제목을 24~28px로 조정할 수 있다. 본문은 기본 16px을 유지한다.
- 화면에 표시하는 문구는 짧고 친근한 존댓말로 작성한다. 예: “분석이 완료됐어요”, “파일을 확인해 주세요”.
- 버튼은 “분석하기”, “다시 시도하기”, “결과 저장하기”처럼 행동을 설명한다.
- 레이블 끝에는 마침표를 생략한다. 완결된 안내 문장은 자연스러운 문장부호를 사용한다.
- 오류 문구에는 원인과 해결 방법을 포함한다. 예: “필수 컬럼이 없어요. 날짜와 금액 컬럼이 있는 파일을 올려 주세요.”
- 화면 맞춤용 강제 줄바꿈을 반복하지 않는다. 긴 한국어 문장과 URL은 컨테이너를 넘지 않게 처리한다.

## 5. 레이아웃·간격·반응형

기본 화면은 **페이지 제목·짧은 설명 → 입력·옵션 → 실행 → 결과 → 추가 정보** 순서로 구성한다. 데이터 앱에 불필요한 대형 소개 배너를 넣지 않는다.

- 콘텐츠는 가운데 정렬하고 좌우 여백을 유지한다. 폼은 과도하게 넓히지 않고 약 640~720px 안에서 읽기 편하게 배치한다.
- 화면이 넓고 비교가 필요하면 입력과 결과를 2열로 구성한다. 모바일에서는 입력 다음에 결과가 오도록 1열로 배치한다.
- 페이지 기본 간격은 `8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64px` 중에서 선택한다.
- 레이블과 입력은 8px, 필드 사이는 20~24px, 카드 내부는 20~24px, 주요 섹션 사이는 32~48px를 기본으로 한다.
- 카드·결과 그리드의 거터는 20px을 기준으로 한다. 모바일 바깥 여백은 16px, 태블릿 이상은 24px을 기본으로 한다.

| 구간 | 뷰포트 너비 | 배치 기준 |
|---|---|---|
| xs | 0~767px | 주요 흐름 1열, 버튼은 필요하면 전체 너비 |
| sm | 768~991px | 넓이에 따라 1~2열, 긴 필드와 결과는 전체 너비 |
| md | 992~1199px | 필요한 경우 입력·결과 2열 |
| lg | 1200~1599px | 바깥 패딩을 포함한 최대 콘텐츠 너비 1100px |
| xl | 1600px 이상 | 기본 최대 너비 유지. 넓은 표·대시보드만 필요에 따라 1440px까지 확장 |

최대 너비는 컨테이너의 `box-sizing: border-box` 기준이다. 브레이크포인트마다 별도 화면을 만들 필요는 없으며, 필요한 배치 변경에만 사용한다.

- 긴 표는 표 영역 안에서 가로 스크롤을 제공한다. 페이지 전체의 가로 넘침은 방지한다.
- 고정 높이로 본문이나 결과를 자르지 않는다. 긴 텍스트·큰 수치·긴 파일명을 확인한다.
- 이미지가 필요하면 일정한 비율을 사용하고, 실제 이미지가 없을 때의 대체 상태도 구성한다.

## 6. 컴포넌트 기준

| 요소 | 크기·모양 | 동작·내용 |
|---|---|---|
| 주요 버튼 | 기본 높이 48px, 라운드 12px, 16px/700 | 파란 바탕과 흰 글자. 같은 작업 영역의 주요 행동 하나를 강조 |
| 보조 버튼 | 주요 버튼과 같은 높이, 흰 바탕·얇은 테두리 | 취소, 초기화 등 보조 행동 |
| 작은 버튼 | 데스크톱에서 높이 40px, 라운드 10px | 모바일에서는 실제 클릭 영역을 44×44px 이상으로 확보 |
| 입력·선택 필드 | 높이 48px, 라운드 12px, 좌우 패딩 16px | 레이블·입력 예시·도움말·오류 영역을 구분 |
| 여러 줄 입력 | 최소 높이 96px, 패딩 12px 16px | 긴 입력을 허용하고 필요한 길이 기준 안내 |
| 기본 카드 | 라운드 16px, 패딩 20~24px, 1px 얇은 테두리 | 그림자 없이 제목·내용·관련 행동으로 구성 |
| 필터 칩 | pill 형태, 선택 여부를 색·굵기 등으로 표시 | 선택 상태를 보조 기술에도 전달하고 클릭 영역 확보 |
| 데이터 표 | 헤더 13px/600, 본문 14px/500 | 숫자는 오른쪽 정렬, 단위 표시, 필요하면 숫자 너비 일정하게 처리 |
| 인라인 알림 | 라운드 12px, 패딩 14px 16px | 상태 아이콘·제목·설명·필요한 다음 행동 |
| 드롭다운·모달 | 흰 표면·얇은 테두리·오버레이 그림자 | 화면 위에 뜨는 경우에만 그림자 적용 |

- 주요 버튼은 hover에서 어두운 반투명 층 7.5%, active에서 18%를 덮는 방식으로 일관되게 처리한다.
- 입력은 focus에서 파란 테두리와 포커스 링을 보여 준다. 오류 입력에는 오류 문구를 연결한다.
- disabled 상태의 이유를 필요한 경우 설명한다. 실제 입력 오류는 실행 후에도 해당 필드 옆에서 안내한다.
- 아이콘은 하나의 일관된 세트를 선택하고, 기본 24px과 `currentColor`를 사용한다. 기능 아이콘을 이모지로 대체하지 않는다.
- 아이콘만 있는 버튼에는 접근 가능한 이름을 제공한다. 장식 아이콘은 중복해서 읽히지 않게 한다.
- 모달은 필요한 작업에만 사용한다. 열릴 때 포커스를 이동하고, 내부 키보드 이동과 닫힌 뒤의 포커스 복귀를 처리한다.

## 7. 필수 화면 상태

아래 상태는 해당 기능에 맞춰 구현한다. 모든 기능에 별도 페이지를 만들 필요는 없다.

| 상태 | 보여 줄 정보 | 사용자의 다음 행동 |
|---|---|---|
| 초기 | 서비스 목적, 입력 방법, 필요한 형식과 샘플 | 입력하거나 샘플 선택 |
| 입력 오류 | 문제가 있는 필드와 해결 가능한 설명 | 해당 필드 수정 |
| 로딩 | 진행 중인 작업 이름, 로더, 중복 실행 방지 | 완료 대기, 지원되는 경우 취소 |
| 성공 | 핵심 결과, 단위·조건·데이터 출처 등 필요한 근거 | 결과 확인, 실제 제공하는 저장·다운로드 실행 |
| 빈 입력·빈 결과 | 입력이 없는지, 조건에 맞는 결과가 없는지 구분 | 입력 추가, 조건 변경 또는 초기화 |
| API·네트워크 실패 | 작업이 완료되지 않았다는 안내와 복구 방법 | 입력을 유지한 채 다시 시도 |
| 키 누락·설정 오류 | 설정이 필요한 상태임을 간단히 안내 | 실행 환경 설정 확인 |

- 진행률을 알 수 없으면 퍼센트나 가짜 완료 시간을 표시하지 않는다.
- 복구가 필요한 오류와 필수 안내는 자동으로 사라지는 토스트에만 넣지 않는다.
- 재시도 시 입력을 보존하고, 실패한 상태에서 이전 결과가 새 결과처럼 보이지 않게 한다.
- 사용자 화면에는 인증키·스택 트레이스·내부 경로를 표시하지 않는다.

## 8. 접근성과 모션

- 프로젝트의 텍스트 대비 목표는 일반 본문 4.5:1 이상이다. 실제 색상과 배경의 조합으로 확인한다.
- 기능을 구분하는 테두리·아이콘은 충분한 대비를 확보한다. 연한 장식용 구분선과 구분해 검토한다.
- 키보드만으로 입력 → 실행 → 결과 확인이 가능해야 한다. 포커스 표시를 제거하지 않는다.
- 키보드 포커스는 기본 `2px solid var(--brand-primary)`와 `2px` offset으로 표시한다. 파란 버튼처럼 배경과 겹치면 흰 간격과 바깥 링으로 구분한다.
- 모바일에서 조작 요소의 실제 터치 영역은 최소 44×44px을 확보한다. 아이콘의 그림 크기와 클릭 영역을 구분한다.
- 결과·오류처럼 동적으로 바뀌는 정보는 적절한 상태 안내로 전달한다. 과도한 자동 포커스 이동은 피한다.
- hover·focus 변화는 100~150ms ease, 필요한 화면 전환은 약 200ms의 짧은 fade를 기본으로 한다.
- 반복되는 장식 애니메이션, bounce, parallax를 추가하지 않는다. 동작 줄이기 설정에서는 불필요한 모션을 줄인다.

## 9. HTML·Streamlit 구현 원칙

- HTML에서는 위 색상 토큰과 공통 컴포넌트 스타일을 한곳에서 관리한다.
- Streamlit에서는 현재 버전의 테마·레이아웃·기본 위젯 설정을 우선 사용하고, 지원 범위를 확인한 뒤 필요한 부분만 확장한다.
- Streamlit의 기본 설정이 HEX 색상만 받으면 위 토큰의 HEX 앵커를 사용한다. 반투명 레이어를 적용할 수 없는 설정에 rgba 값을 억지로 넣지 않는다.
- 자동 생성된 CSS 클래스명, 위젯 순서에 의존하는 선택자, 광범위한 스타일 덮어쓰기는 피한다. 커스텀 스타일은 범위를 좁힌다.
- 기본 위젯에서 치수를 완전히 맞출 수 없으면 주요 색상·위계·입력 흐름·상태 표현을 우선하고 차이를 기록한다.
- 스크린샷을 위해 가짜 결과·비활성 버튼을 실제 기능처럼 만들지 않는다. 샘플은 샘플임을 표시한다.
- 외부 폰트·아이콘·컴포넌트를 실제 도입하면 출처와 필요한 라이선스 고지를 관리한다.

## 추가 화면: 계정·카메라·기록

- 헤더의 로그인·가입과 내 기록을 보조 행동으로 배치한다. 좁은 화면에서는 메뉴를 다음 줄로 배치하고 가로로 이동할 수 있게 한다.
- 로그인(`/login`)과 회원가입(`/register`)은 각각 독립 페이지로 제공한다. 공통 브랜드 헤더와 중앙 폼 카드를 사용하고, 레이블·입력 규칙·처리 중·입력 오류 상태를 표시한다. 회원가입에 비밀번호 확인을 제공하며 두 페이지 사이를 링크로 이동한다. 가입·로그인 완료 후 분석 화면으로 돌아오고, 계정 전환 시 이전 계정의 개인 정보를 화면에 남기지 않는다.
- 카메라 모달에는 미리보기, 전·후면 전환, 촬영, 항상 사용할 수 있는 닫기를 둔다. 전면 미리보기 반전 여부와 촬영 후 분석 단계가 구분되게 안내한다. 권한 거절·장치 없음·촬영 실패 안내를 제공한다.
- 기록은 저장 일시·모델·요약, 보기·삭제를 표시한다. 빈 목록과 불러오기 실패 상태를 안내하고, 삭제 전 확인한다. 원본 사진은 보관하지 않음을 기록 화면에 표시한다.
- 내 기록 모달은 연한 파란색 헤더, 저장 리포트 수, 날짜 배지가 있는 개별 카드, 고정 안내 푸터로 구성한다. 본문 목록만 스크롤하고 요약·모델·리포트 보기·삭제를 구분한다. 한국 시간 기준 날짜·시간을 표시하며, 로딩에는 정적인 스켈레톤, 빈 목록에는 관찰 화면으로 이동하는 행동을 제공한다. 모바일에서는 카드 간격과 패딩을 줄이고 내용·버튼이 자연스럽게 줄바꿈되게 한다.
- 사진 선택 영역에 접을 수 있는 학습 등록 폼을 제공한다. 사진 라벨·익명 사람 그룹과 저장 위치를 안내하고, 즉시 로컬 저장과 분석 후 저장을 선택할 수 있게 한다. 저장 성공·데이터 부족·학습 완료·학습 실패를 구분하며, 사진이 저장된 경우 재등록 버튼을 막고 학습 목록으로 연결한다. 모바일에서는 입력을 한 열로 배치한다.
- 학습 가이드(`/training-guide`)는 학습 횟수의 핵심 답변, 계정별 준비 상태, 최소 사진 구성 예시, 재학습 시나리오, 사용 순서, FAQ 순서로 구성한다. 진행 막대는 필요한 사진 수에 대한 준비 정도이며 분류 확률로 표현하지 않는다. 비로그인 상태에는 수치를 만들어 표시하지 않고 로그인 행동을 제공한다. 모바일에서는 설명과 준비 상태 카드를 세로로 배치한다.
- 카메라·기록 모달은 기존 색상·테두리·16px 카드 반경을 사용하며 배경을 어둡게 한다. 기본 dialog의 포커스 제한과 Escape 닫기를 활용한다. 화면 높이를 넘으면 모달 안에서 스크롤한다. 계정 페이지도 같은 색상·반경을 사용하고 모바일에서는 카드 여백을 줄인다.

## 10. 구현 후 확인 기준

- [ ] 주요 행동과 입력 → 실행 → 결과의 순서가 명확하다.
- [ ] 색상·타이포그래피·간격을 이 문서의 기준으로 일관되게 사용했다.
- [ ] 초기·로딩·성공·오류·빈 결과 상태를 해당 기능에서 확인했다.
- [ ] 정상 입력뿐 아니라 잘못된 형식·빈 값·실패 응답을 확인했다.
- [ ] 360px 안팎의 작은 화면과 태블릿·데스크톱에서 넘침과 잘림을 확인했다.
- [ ] 긴 한국어 문장·파일명·URL·큰 수치를 확인했다.
- [ ] 키보드 이동, 포커스 표시, 레이블, 터치 영역과 실제 색상 대비를 확인했다.
- [ ] API 키와 내부 오류 정보가 화면에 노출되지 않는다.
- [ ] 선택한 구조와 화면 상태가 개발자 관점의 동작·오류 처리 설명에 연결된다.

주요 화면과 예외 처리 화면을 캡처하고, 선택 이유와 구현상 차이를 짧게 남긴다. 과제의 개선 전후 측정과 AI 활용 기록은 [스킬 규칙.md](<./스킬 규칙.md>)의 기준에 맞춰 함께 정리한다.

## 분석 페이지의 추가 디자인 기준

사용자 요청에 따라 사진 분석 페이지는 [분석 페이지 디자인 기준](docs/analysis-design.md)을 함께 적용한다. 사용자 제공 SEED Design 문서의 역할 기반 표면, 둥근 액션 버튼, 선택 카드와 접이식 항목의 구조를 참고하되, 이 문서의 파란색·중성색·글꼴·공통 화면 규칙을 유지한다. 전용 스타일은 분석 본문에만 적용한다.
