# Hairline Lab 개발 기록

작성일: 2026-10-28

## 사용자 요청과 구현 범위

- 개발자 직군의 5일 개인 프로젝트다.
- 원티드 참고 디자인을 기반으로 탈모 판별 사이트를 요청했다.
- Gemini 2.5 Flash, MediaPipe, OpenCV, 선택적 Stable Diffusion 인페인팅과 Gemini 이미지 생성 API를 연결한다.
- API 키는 `.env`로 분리하고, 우선 사용자 컴퓨터에서 실행한다.

## 선택한 구조와 이유

- 화면은 HTML·CSS·JavaScript, 서버는 Flask·Waitress로 구성했다. Python의 MediaPipe·OpenCV를 직접 사용하면서 비밀키를 브라우저에 보내지 않기 위한 선택이다.
- 로그인·DB·사진의 영구 저장을 추가하지 않았다. 사진은 요청 중 메모리에서 처리하고, EXIF 등 메타데이터를 제거한다.
- 사진 관찰과 가상 외형 편집을 분리했다. 임상적으로 검증하지 않은 확률·중증도·진행 예측을 생성하지 않도록 분석 프롬프트와 결과 형식을 제한했다.
- 외부 전송은 Gemini 요청을 선택한 경우에만 수행한다. 사진 전송 동의를 받고, 유료 이미지 생성에는 서버 설정과 별도의 요청별 확인을 요구한다.
- 로컬 인페인팅은 큰 모델을 자동 다운로드하지 않는다. 추가 패키지·호환 로컬 모델·CUDA GPU가 있을 때만 실행하는 실제 어댑터를 제공했다.
- 기본 시스템 Python 3.15 대신 별도의 프로젝트 Python 3.12 가상환경을 준비했다.

## 실제 수정·검증 사례

- MediaPipe 설치 과정에서 OpenCV 패키지 두 종류가 중복 설치되어, `opencv-contrib-python` 하나로 정리하고 의존성을 고정한 파일을 기록했다.
- 단순 합성의 피부색 샘플이 머리 아래 배경을 고를 수 있어, 중앙의 비모발 영역 중 피부색 후보를 먼저 샘플링하도록 수정했다. 다양한 피부색·조명에서 완벽한 결과를 보장하지 않으며 UI에 간단 합성의 한계를 표시한다.
- 사진과 별개로 `.env`·Python 코드·모델 파일이 웹으로 노출되지 않는지 확인했다.
- 유료 생성이 꺼져 있거나 동의가 없으면 외부 호출 자체가 발생하지 않는지 테스트했다.
- 불완전한 Gemini 응답, 잘못된 JSON, 인증 실패, 할당량 초과와 시간 초과를 모의 응답으로 검증했다.

## 프롬프트와 AI 활용

- 분석 프롬프트 버전: `hair-observation-v1`, 원문은 `services/gemini.py`에 있다.
- 입력: 메타데이터를 제거하고 최대 1280px로 줄인 사진과 관찰 요청.
- 출력: 사진 관찰 가능 여부, 관찰 신호, 요약, 부위별 관찰, 한계, 다음 행동의 구조화된 JSON.
- 이미지 속 텍스트의 지시를 따르지 않고 신원·나이·성별을 추측하지 않도록 정했다.
- AI는 초기 코드·화면을 작성했고, 의존성 확인·정적 참조 확인·단위 테스트·실제 로컬 모델 호출로 결과를 검증했다.
- 적용한 작업 가이드: Sites의 로컬 구현·검증 지침, Computer Use의 브라우저 확인 절차, 프로젝트의 `스킬 규칙.md`와 `디자인.md`.
- 실제 API 키가 없어 Gemini v1·v2의 실측 성능 비교는 수행하지 않았다. 수행하지 않은 비교 결과와 정확도를 만들지 않는다.

## 검증 범위와 남은 확인

- API·입력·권한·외부 오류·로컬 합성 관련 자동 테스트 30개를 구성했다.
- 실제 localhost HTTP로 HTML·JS·CSS·상태 API의 200 응답을 확인했다.
- 실제 hair-only TFLite 모델에서 단순 합성 초상화의 모발 마스크를 생성했고, OpenCV의 헤어라인·정수리·밀도 세 유형이 PNG를 반환하는 것을 확인했다.
- 이 합성 초상화는 실행 경로를 검증하기 위한 도형이며, 실제 모발 검출 정확도나 의료 성능의 평가 자료가 아니다.
- 브라우저 자동화가 현재 URL을 신뢰할 수 있게 확인하지 못해 중단되었다. 브라우저 렌더링·모바일 화면·키보드 조작의 직접 검증은 완료하지 못했다.
- 실제 Gemini 분석·이미지 생성은 API 키 입력 후, Stable Diffusion은 로컬 모델·CUDA GPU 준비 후 별도로 확인해야 한다.
- 배포는 사용자 요청에 따라 진행하지 않았다.

## 후속 평가 방법

동의된 평가 사진이나 사용 조건이 맞는 공개 사진으로 같은 입력 집합을 만든다. 먼저 응답 시간과 처리 오류율을 측정하고, 프롬프트를 바꿀 경우 동일 데이터·모델 설정에서 관찰 내용의 적절성과 실패 사례를 비교한다. 임상적 정답이 없는 자료로 탈모 진단 정확도를 주장하지 않는다.

## 2026-10-28: OCR 추가

- 사용자가 OCR 가능 여부를 재확인해, 별도의 문서 이미지 업로드와 한국어·영어·숫자 추출 기능을 추가했다.
- PaddleOCR는 모발 판별을 대체하지 않으며 결과지 등 이미지의 글자 추출만 맡는다. Google API와 연결하지 않는다.
- CPU용 PaddleOCR 3.3.2·PaddlePaddle 3.2.0과 공식 경량 검출·한국어 인식 모델을 사용했다.
- Windows에서 최신 인코딩 감지기와 pandas의 DLL 로딩 오류가 발생해, 호환되는 chardet 5.2.0·pandas 2.2.3으로 고정했다. PaddlePaddle 초기 캐시 생성에 필요한 실행 권한을 확인한 뒤 실제 추론을 검증했다.
- 직접 만든 텍스트 이미지에서 한국어·영어·숫자 3줄을 실제로 추출했다. 영문 `OCR`가 `OcR`로 나오는 대소문자 오인식도 확인했다. 이 결과를 일반적인 OCR 정확도 수치로 주장하지 않는다.
- 사용자가 추출 결과를 수정·복사·TXT 저장할 수 있게 했으며, 빈 결과·잘못된 파일·모델 누락·실행 중 중복 요청을 처리한다.
- 기존 30개에 OCR 테스트 15개를 추가했다. 실제 모델 실행 확인은 `scripts/verify_ocr.py`로 반복할 수 있다.

## 2026-10-28: Gemini 보조 자료와 사진 학습

- OCR 텍스트를 검토한 뒤 별도 동의한 경우에만 Gemini 요청의 참고 데이터로 연결했다. 프롬프트 버전은 `hair-observation-v2-assisted`로 변경했다. 문서의 지시문을 따르거나 문서 내용을 사진의 확정 진단으로 간주하지 않도록 기존 프롬프트에 제한을 추가했다.
- 사용자 라벨 두 종류와 익명 사람 그룹으로 사진을 등록하고 CPU에서 HOG·색상·명암 특징 기반 선형 SVM을 학습하는 기능을 추가했다. OpenCV를 재사용해 새 학습 패키지를 설치하지 않았다.
- 최소 각 라벨 5장·각 라벨 2개 그룹·전체 4개 그룹을 요구한다. 같은 사람은 학습·검증에 동시에 들어가지 않게 분리하고, 스케일링 통계도 학습 데이터에서만 계산한다. 중복·매우 유사한 사진은 등록을 거부한다.
- 모델은 보류 검증 사진으로 재학습하지 않는다. 내부 라벨 일치율·표본 수·다수 라벨 기준선을 표시하며 의료적 정확도나 질환 확률을 제공하지 않는다.
- 학습 등록은 별도 동의 후 사진·특징값을 로컬 저장한다. 이에 맞춰 기존의 사진 비저장 안내를 일반 분석과 학습 등록으로 구체화했다. 데이터 변경 후에는 모델을 재학습할 때까지 사용하지 않는다.
- 검증용 임시 폴더에 합성 패턴 이미지 12장을 만들어 실제 학습·저장·재로딩·분류를 확인했다. 합성 이미지 결과는 학습 경로의 기능 검증이며 실제 탈모 판별 성능을 뜻하지 않는다. 실제 탈모 사진은 제공받거나 학습하지 않았다.
- 로컬 분류 결과의 Gemini 전송도 별도 선택 사항이다. 학습 원본·특징값·그룹 식별자는 전송하지 않는다.
- 검증 결과: 자동 테스트 65개 통과. 임시 합성 데이터로 학습 API·분류 API의 200 응답과 실제 PaddleOCR 3줄 추출을 확인했다. Gemini 보조 전송은 모의 응답으로 동의와 요청 구성을 검증했으며, 실제 사용자 사진의 Gemini 실호출과 임상 성능은 검증하지 않았다.

## 2026-10-28: 카메라·회원가입·SQLite

- 사용자 요청으로 기존 로컬 앱에 카메라 촬영, 아이디·비밀번호 회원가입·로그인, SQLite DB를 추가했다. 기존 Flask·Werkzeug와 Python 기본 SQLite를 재사용하여 추가 설치가 필요하지 않다.
- 카메라는 명시적인 버튼 클릭으로 열고 오디오 없이 전·후면 미리보기를 제공한다. JPEG 촬영 후 기존 사진 선택·전송 동의·분석 흐름으로 연결한다. 창 닫기, 탭 숨김, 계정 변경, 늦은 권한 응답에 대해 미디어 트랙을 해제한다. 실시간 영상은 서버로 보내지 않는다.
- 비밀번호는 scrypt 해시로 저장한다. HttpOnly·SameSite 쿠키와 8시간 만료의 서버 세션 토큰 해시를 사용하며 로그아웃 시 세션을 폐기한다. 모든 변경 요청은 CSRF를 검증하고 로그인 실패 시도를 제한한다.
- DB의 `users`, `sessions`, `analysis_history` 테이블은 첫 실행에 자동 생성한다. 분석 리포트는 로그인 후 사용자가 저장을 선택한 경우에만 보관하며, 원본 분석 사진·OCR 입력 원문은 DB에 넣지 않는다. 리포트에는 AI가 생성한 관찰 내용이 포함된다. 저장에 실패해도 이미 완료된 분석 결과를 반환하고 파일 저장 안내를 제공한다.
- 리포트 조회·삭제와 학습 사진·모델·분류는 계정별로 제한한다. 학습 디렉터리는 `data/training/users/<계정 ID>/`로 분리한다. 기존 공용 학습 폴더를 임의의 새 계정에 연결하지 않는다.
- 로그아웃·계정 변경 시 사진·OCR·리포트·학습 목록을 지우고, 브라우저에서 대기 중인 요청과 업로드 반복을 중단하며 이전 계정의 늦은 응답을 폐기한다. 서버가 이미 처리 중인 요청의 실행 자체를 되돌리는 기능은 아니다.
- 검증: Python 자동 테스트 79개와 Node의 로그인·카메라 테스트 9개를 구성했다. 비밀번호 해시, CSRF, 세션 폐기·만료, 계정 간 접근 차단, 리포트 저장 동의·삭제, DB·세션 재시작 유지와 카메라 권한·촬영·해제를 확인했다. 실제 localhost HTTP에서도 회원가입·세션 쿠키·기록·학습 상태·로그아웃을 확인했다. 검증 계정과 데이터는 임시 DB에서만 사용했고 기본 DB에는 계정을 만들지 않았다.
- 실제 웹캠과 브라우저 렌더링 검증은 완료하지 못했다. 브라우저 자동화 연결이 제공되지 않아 카메라 동작은 모의 미디어 장치로 검증했다. Gemini 실호출·의료 성능은 이번 변경의 검증에 포함하지 않았다. 서버는 계속 `127.0.0.1` 로컬 실행용이며 배포하지 않았다.

## 2026-10-28: 로그인·회원가입 페이지 분리

- 요청에 따라 로그인(`/login`)과 회원가입(`/register`)을 독립 페이지로 분리했다. 메인 헤더에 각각 링크를 두고 기존 계정 모달을 제거했다. 공통 Jinja 레이아웃과 별도 폼 템플릿으로 기존 브랜드·색상·반응형 입력 화면을 유지한다.
- 기존 SQLite 계정·세션 API와 CSRF를 그대로 연결했다. 가입·로그인 성공 후 분석 화면이나 진입했던 로컬 학습 화면으로 돌아간다. 외부 URL·인증 페이지·API 주소를 복귀 대상으로 사용하지 않는다. 이미 로그인한 사용자는 폼 대신 해당 앱 화면으로 이동한다.
- 회원가입의 비밀번호 일치 확인, 로그인 오류·서버 연결 실패 안내, 중복 제출 방지, 제출 후 비밀번호 정리와 브라우저 뒤로가기 캐시 갱신을 처리했다.
- 현재 작업 폴더 기준 Python 테스트 84개, Node 테스트 14개가 통과했다. 별도 페이지 렌더링·상호 링크·복귀 경로 검증과 기존 인증·카메라·데이터 격리를 포함한다. 실제 localhost HTTP에서 페이지·정적 파일·가입·로그인·세션·로그아웃·안전한 복귀를 확인했고 테스트 계정은 메모리 DB에서만 생성했다.
- 메인·로컬 학습·로그인·회원가입의 HTML ID 중복, 스크립트가 참조하는 요소와 정적 파일 연결을 확인했다. 브라우저 접근 호스트가 제공되지 않아 실제 렌더링·키보드 조작의 직접 확인은 완료하지 못했다.

## 2026-10-28: 분석 화면의 사진을 로컬 학습에 등록

- 실제 고정 헤더 높이와 32px 여백을 기준으로 섹션을 선택하며, 하단의 짧은 마지막 섹션·초기 해시 이동·뒤로가기 복귀·리사이즈도 처리한다. 분석 결과나 챗봇 열림에 따라 메인 크기가 달라지면 ResizeObserver로 갱신한다. 스크롤 이벤트는 프레임당 한 번 처리하고, 현재 메뉴가 모바일 가로 메뉴 밖에 있을 때 메뉴만 수평 이동한다. URL·페이지 스크롤·키보드 포커스를 임의로 변경하지 않는다.
- 챗봇을 브랜드 아이콘·헤더·선택형 안내 배지, 주제별 아이콘 카드, 파란색 사용자 말풍선과 도우미 답변 카드, 문항별 진행 표시와 응답 요약 배지로 정리했다. 선택 버튼의 접근 가능한 이름을 유지하고 자가 테스트의 ‘네·아니요’는 같은 강조 수준으로 표시한다. 기존 고정 답변·분기·저장하지 않는 동작을 유지한다.
- 검증: 새 메뉴 추적 테스트 7개와 기존 챗봇·계정·카메라·학습 테스트 32개, 총 39개 통과. 메뉴 하향·상향 이동, 초기 위치·복귀, 페이지 하단, 헤더·메인 크기 변경, 이벤트 처리 제한, 가로 메뉴·동작 줄이기, 별도 페이지 유지와 챗봇 응답 흐름을 검증했다. JavaScript 구문과 HTML ID·레이블·앵커·DOM·아이콘 참조를 점검했고 실제 localhost에서 메인·메뉴 JS·챗봇 JS/CSS·공통 CSS·아이콘의 200 응답과 파일 일치를 확인했다.
- 화면 직접 검증을 다시 시도했으나 브라우저 접근 호스트가 없고 Whale 창 연결이 갱신 후에도 같은 소유자 확인 오류를 반환했다. 실제 스크롤·모바일 터치·화면 렌더링의 직접 확인은 완료하지 못했다.

### 챗봇 최소화 상태·헤더 변경

- 열린 패널·최소화 바·기본 실행 버튼의 세 상태를 구분했다. 헤더의 ‘−’는 우측 하단 최소화 바로 접고, ‘×’는 기본 실행 버튼으로 닫는다. 최소화 바에서 현재 문항·결과·안내 상태를 확인하고 이어서 열 수 있다. 최소화 동안 메인 화면은 사이드 패널 공간을 사용하지 않는다.
- 헤더를 파란색 바탕·흰색 제목·대화 아이콘으로 변경하고 최소화와 닫기 버튼을 나란히 배치했다. 두 버튼은 44px 조작 영역과 별도 접근성 이름을 제공한다. 최소화 바에도 복원과 닫기를 분리하고, 조작 후 포커스를 보이는 버튼으로 이동한다.
- 접고 다시 열어도 현재 질문과 응답은 유지한다. 계정 변경 시 이전 응답과 최소화 바의 진행 문구를 초기화하며, 화면 크기를 바꾸어도 사용자가 선택한 최소화 상태를 유지한다. 저장소나 외부 API는 사용하지 않는다.
- 검증: 최소화·현재 문항/결과 복원, 최소화 바 닫기·FAQ 유지, 화면 크기·계정 변경 관련 테스트 3개를 추가해 전체 Node 테스트 42개 통과. JavaScript 구문, HTML ID·레이블·ARIA 연결·DOM 참조·아이콘을 점검하고 실제 HTTP에서 메인·챗봇 JS/CSS·아이콘의 200 응답과 파일 일치를 확인했다. 화면 렌더링은 기존 브라우저 연결 제한으로 직접 검증하지 못했다.

### 사용자 이름에서 여는 내 정보 페이지

- 사용자 요청에 따라 메인·로컬 학습·학습 가이드의 사용자 이름을 `/profile` 링크로 바꾸고, 별도 내 정보 페이지를 추가했다. 모바일에서도 이름 링크를 표시하며 긴 아이디는 줄임표와 전체 이름 툴팁으로 안내한다.
- 기존 세션으로 인증한 본인의 아이디·가입일, 저장 리포트 총수·최근 저장일, 학습 사진 수와 모델 상태를 표시한다. DB는 필요한 컬럼만 선택하고 리포트 총수는 최근 50개 목록 제한과 별도로 계산한다. 다른 사용자 ID 쿼리로 조회 계정을 변경할 수 없고 비밀번호·해시·세션 토큰은 페이지에 전달하지 않는다. 날짜는 한국 시간으로 표시한다.
- 비로그인·세션 만료 시 로그인 페이지로 이동하고 로그인 후 `/profile`로 복귀한다. 서버와 로그인 화면의 허용 복귀 경로에 `/profile`을 추가했다. 페이지에서 로그아웃하거나 계정이 바뀌면 이전 계정의 본문을 숨긴 후 해당 로그인·프로필 화면으로 이동한다.
- 내 기록 링크는 `/#history`로 이동하여 인증 확인 후 기존 기록 모달을 연다. 비로그인 상태에서는 로그인 후 기록으로 복귀한다. 로컬 학습·가이드·새 분석 링크도 연결했다. 계정 정보 수정·비밀번호 변경·회원 탈퇴는 이번 요청에 추가하지 않았다.
- 검증: 계정 Python 테스트 24개, Node 테스트 47개로 총 71개 통과. 로그인 보호·복귀, 계정 간 표시 분리, 52개 리포트의 정확한 총수, 한국 날짜, 학습 요약, 세션 만료, 이전 계정 본문 정리, 기록 바로 열기를 검증했다. 임시 DB·임시 학습 폴더로 메인·학습·가이드·내 정보의 HTML ID·레이블·링크·정적 파일·SVG 연결을 점검했다.
- 포트와 실행 경로를 확인한 현재 프로젝트의 로컬 Python 서버만 재시작해 새 경로를 적용했다. 기존 DB와 세션 저장 방식을 유지했고 실제 HTTP에서 `/profile`의 로그인 리다이렉트와 새 JS·CSS의 200 응답·파일 일치를 확인했다. 실제 사용자 계정·기록을 테스트용으로 변경하지 않았다. 실제 화면 렌더링은 기존 브라우저 연결 제한으로 직접 검증하지 못했다.

### 화면 변경 없는 웹소켓 기능

- 사용자 요청에 따라 화면 요소를 추가하지 않고 `services/realtime.py`와 `static/realtime.js`로 웹소켓 전송 기능을 추가했다. 기존 HTTP 서버는 유지하고 같은 프로세스의 별도 스레드에서 `127.0.0.1:8001/ws`를 연다. `websockets` 17.3 한 패키지만 설치하고 요구사항·버전 고정 파일을 갱신했다. [공식 스레드 서버 문서](https://websockets.readthedocs.io/en/stable/reference/sync/server.html)와 설치 버전의 함수 시그니처를 확인했다.
- 로그인 세션 쿠키와 DB의 세션 만료를 확인하고 연결마다 접속한 계정에 묶는다. 접속 페이지와 호스트 이름·HTTP 포트가 일치하는 Origin만 허용하며 URL 인증 토큰이나 외부 호스트 연결은 사용하지 않는다. 로그아웃·재로그인으로 폐기된 세션과 만료된 세션은 연결 중에도 다시 확인해 닫는다.
- ping/pong, 실제 계정 현황 조회, `history`·`training` 변경 구독을 지원한다. 기존 HTTP API에서 리포트 저장·삭제, 학습 사진 추가·삭제, 학습이 성공하면 같은 계정 구독자에 변경 신호만 보낸다. 사진·분석 내용·OCR 원문·그룹 코드·사용자 ID는 알림에 넣지 않는다. 다른 계정 구독이나 웹소켓을 통한 데이터 변경 명령은 받지 않는다.
- 메시지 크기 4KB·분당 60건, 계정당 연결 4개·전체 32개, 연결당 알림 대기열 32개로 제한했다. HTTP 처리와 소켓 전송은 대기열로 분리하고 대기열이 넘치면 재연결을 요구한다. 중지 시 소켓을 정리한다. 로컬 단일 프로세스 범위로 구현했으며 다중 서버 브로드캐스트는 포함하지 않았다.
- 메인·학습·가이드·내 정보에서는 로그인 확인 후 자동 연결하며 `realtime-message`·`realtime-state` 이벤트와 `window.HairlineRealtime` 제어 함수를 제공한다. 화면·고정 답변 챗봇의 동작은 바꾸지 않았다. 비정상 연결 종료 시 최대 5회 지수 간격으로 재연결하고, 계정 변경·로그아웃·페이지 종료 시 연결·타이머를 정리하며 이전 계정의 늦은 응답을 폐기한다.
- 검증: 실제 TCP 웹소켓 테스트 17개와 브라우저 전송 코드 테스트 8개를 추가했다. 인증·Origin·경로·계정/주제 분리, 실제 프레임 송수신, 저장·학습 알림, 세션 폐기/만료, 잘못된 메시지·바이너리·용량·속도·연결 수·대기열 제한, 재연결 상한·이전 응답 폐기를 확인했다. 전체 Python 테스트 115개와 Node 테스트 55개, 총 170개 통과. 모의 학습 실패 로그는 의도한 실패 경로 검증에서 출력되었으며 테스트는 성공했다.
- 포트·프로세스 경로를 확인한 현재 프로젝트 서버만 재시작해 적용했다. 실제 실행 서버에서 HTTP 8000·웹소켓 8001 응답, 최신 클라이언트 파일과 CSP, 비로그인 설정 조회·웹소켓의 401 응답과 외부 Origin의 403 응답을 확인했다. 테스트는 임시 계정·DB·학습 폴더를 사용했고 실제 사용자 계정·기록을 변경하지 않았다. 브라우저 실제 연결은 기존 UI 자동화 제한으로 직접 확인하지 못했으며 브라우저 코드는 모의 WebSocket으로 검증했다.

### 별도 사진 분석 페이지·관찰 기능과 디자인 개선

- 사용자 요청에 따라 사진 분석을 공개 전용 페이지 `/analysis`로 분리했다. 사진 선택·카메라·관찰 설정·리포트·모발 영역·로컬 분류·선택적 학습 저장을 옮겼고, 동일 사진을 쓰는 가상 비교는 `/analysis#simulation`에서 이어서 사용한다. 메인은 소개·분석 진입·이용 안내·기술 상태로 정리하고 분석·카메라 스크립트를 실행하지 않는다.
- 메인·학습·학습 가이드·내 정보·챗봇의 분석 진입을 연결했다. 이전 `/#analysis`·`/#simulation` 주소는 새 페이지로 옮기며, 서버·로그인 화면의 허용 복귀 경로에도 `/analysis`를 추가했다. 메인 내 기록에서 리포트를 누르면 `/analysis?report=<ID>`로 이동해 기존 본인 소유 확인 API로 불러온다. 새 사진이나 다른 계정으로 바뀐 뒤 도착한 이전 기록 응답은 폐기한다.
- 화면은 사진 준비 → 관찰 설정 → 리포트 확인의 3단계 상태 표시, 분리된 입력 카드, 데스크톱에서 스크롤 가능한 결과 패널, 모바일의 순차 배치로 재구성했다. 작은 화면은 분석 완료·오류 시 결과로 이동하고 동작 줄이기 설정을 따른다. 오류·안내 메시지는 결과 패널에서 표시한다. 메인 소개 문구의 작은 글자 크기는 유지했다.
- 사진을 선택하면 브라우저 캔버스에서 전체 밝기와 크기를 점검한다. 낮은 해상도·극단적인 전체 밝기는 촬영 도움말로 안내할 뿐 자동 분석 차단이나 모발 품질·진단 점수로 쓰지 않는다. 이 점검은 서버·Google 요청을 하지 않는다. 초기화·계정 변경 시 사진과 점검 표시를 함께 지운다.
- 전체·헤어라인·정수리/가르마·모발 분포 선택을 실제 분석 요청에 연결했다. 서버와 모델 어댑터에서 허용값을 검증하고 버전 `hair-observation-v3-focused` 프롬프트에 고정된 부위별 지침을 추가한다. 의료 진단·단계·확률·미래 예측 금지 지침과 결과 스키마는 유지하고, 밀도 선택도 실제 밀도·모낭 수 추정으로 해석하지 않는다. 선택값은 저장 리포트에도 보관한다.
- 리포트 내용 복사·한글 텍스트 저장을 추가하고 기존 JSON 저장을 유지했다. 내 기록을 열 때는 원본 사진 복원이나 AI 재호출 없이 저장 결과를 표시한다. 기존 학습 라벨의 잘못된 닫기 태그(`</option value=...>`)를 구조 검증에서 발견해 올바른 선택 항목으로 수정했다.
- 검증: Python 테스트 119개와 Node 테스트 68개, 총 187개 통과. 별도 페이지·공개 진입·부위 검증과 모델 전달·고정 프롬프트·저장, 실제 분석 페이지 ID를 쓰는 모의 DOM의 선택/초기화·진행·복사/저장·저장 기록·이전 응답 폐기, 메인 이전 주소·서비스 상태, 기록 이동·로그인 복귀·메뉴 상태를 검증했다. HTML 중첩·ID 중복·레이블·ARIA·SVG·파일 참조와 분석 스크립트의 필수 DOM을 점검했다.
- HTTP·웹소켓의 포트와 실행 경로를 확인한 서버만 재시작해 적용했다. 실제 `/analysis`와 최신 자산의 200 응답·파일 일치·비저장 캐시, 잘못된 관찰 부위의 400 응답, 기존 웹소켓의 인증 거부 동작을 확인했다. 새 촬영이나 실제 Gemini 호출은 수행하지 않았고 실제 사용자 데이터는 변경하지 않았다. AI 정확도 향상이나 임상 성능을 측정하지 않았으며, 실제 브라우저 렌더링은 기존 연결 제한으로 직접 확인하지 못했다.

### 분석 상단 정리·관찰 리포트 문어 일러스트

- 사용자 요청에 따라 분석 페이지 제목 위의 독립된 ‘홈’ 링크를 제거했다. 작은 분석 배지와 간결한 소개 문구로 정리하고, 촬영·이용 안내 링크는 얇은 테두리 버튼으로 다듬었다. 모바일에서는 제목과 안내 버튼이 자연스럽게 줄바꿈된다.
- 관찰 리포트의 사람 일러스트를 관찰 노트를 든 귀여운 파란 문어로 교체했다. 기존 벡터 자산에 맞춰 `static/report-octopus.svg`를 직접 작성하고, 리포트 대기 안내를 짧은 문구와 관찰 내용·사진의 한계·다음 행동의 작은 배지로 정리했다. 분석·저장·기록의 요소 ID와 동작은 유지했다.
- 검증: 실제 분석 페이지 DOM을 사용하는 기존 Node 테스트 7개 통과. HTML ID 중복·레이블 연결·아이콘 참조, 새 SVG의 XML 구조를 점검했다. 실제 `/analysis`·전용 CSS·문어 SVG의 HTTP 200 응답과 디스크 파일 일치를 확인했다. 브라우저 렌더링은 기존 연결 제한으로 직접 확인하지 못했다.

### 별도 변화 미리보기 페이지·가상 편집 공간 개선

- 사용자 요청에 따라 분석 페이지의 ‘02 / EXPLORE’ 편집 섹션을 공개 전용 페이지 `/simulation`으로 분리했다. 모든 페이지의 상단 메뉴와 메인 진입 링크를 연결하고, 기존 `/#simulation`·`/analysis#simulation` 주소도 새 페이지로 옮긴다. 서버와 로그인 화면의 안전한 복귀 경로에 새 주소를 추가했다.
- 입력 카드와 비교 패널을 분리하고 사진 준비 → 변화 설정 → 비교·저장의 단계를 표시했다. 독립적인 사진 선택·드래그·카메라, 부위 선택, 강도 빠른 선택, 실제 준비 상태에 따른 편집 방식, 로딩·대기 취소·실패·재시도 안내를 제공한다. 기존 문어 벡터를 빈 비교 화면에 재사용하고 작은 화면에서는 순차 배치한다. 터치 조작 영역과 키보드 포커스를 유지했다.
- 기존 `/api/simulate`에 연결해 슬라이더·나란히 비교 전환과 비교 위치 초기화를 추가했다. 사진·설정 변경 시 이전 결과를 지우고, PNG 저장에는 가상 편집 안내를 덧붙인다. 기본 합성은 실제 모발 분할·OpenCV 준비 상태를 확인하고, Google 편집은 별도의 전송 동의와 비용 확인을 모두 요구한다. AI 모델·프롬프트·실제 예측 성능은 변경하지 않았다.
- 분석 화면의 ‘이 사진으로 변화 비교’를 누를 때만 선택한 원본 File을 브라우저 IndexedDB에 한 장 임시 보관한다. 무작위 일회용 키, 계정 일치, 5분 유효기간을 확인하고 읽기와 삭제를 한 트랜잭션에서 처리한다. 만료 데이터는 다음 접근 때 정리하며 이후 계정 변경에도 정리한다. 일반 메뉴 이동·사진 선택만으로 전달하거나 서버에 전달용 사진을 저장하지 않는다. 저장소 사용이 불가능하면 새 페이지에서 직접 사진을 선택하도록 안내한다.
- 분석·편집 컨트롤러를 분리하고 공통 카메라의 촬영 후 포커스 대상을 각 페이지 실행 버튼에 맞췄다. 사진 전달 중 계정 변경, 늦은 이미지 생성·전달 응답, 새 사진 선택, 페이지 복귀를 처리했다. 대기 취소는 브라우저 대기만 종료하며 이미 시작한 서버 처리·유료 비용을 취소하지 않는다고 안내한다.
- 검증: 관련 Python 테스트 60개와 전체 Node 테스트 87개, 총 147개 통과. 독립 페이지·자산·인증 복귀·기존 합성 API, 실제 편집 HTML ID를 사용하는 모의 DOM의 입력·설정 전달·비교·저장·동의·실패/재시도·취소·계정 변경, 일회용 전달·소유자 분리·만료·저장소 실패·늦은 응답·카메라 포커스를 검증했다. HTML 중첩·ID·레이블·ARIA·정적 자산·아이콘·새 컨트롤러 DOM 참조도 점검했다.
- 경로·명령·8000/8001 포트 소유권을 확인한 현재 프로젝트 서버만 재시작했다. 실제 새 페이지·수정 자산의 HTTP 200·디스크 파일 일치·비저장 캐시와 로컬 편집 준비 상태, HTTP·웹소켓 시작을 확인했다. 실제 사용자 사진·계정·기록은 변경하지 않았고 유료 API는 호출하지 않았다.
- 적용한 지침: 프로젝트 규칙·디자인 문서와 Sites의 로컬 개발·검증 절차. Computer Use로 화면 검증을 시도했으나 브라우저 접근 호스트가 없고, 현재 Hairline Lab의 Whale 창도 `window id 330210 no longer belongs to Naver_Whale; current owner is Naver_Whale` 오류가 창 목록 갱신 후에도 반복됐다. 실제 브라우저 렌더링·모바일 터치 확인은 완료하지 못했다.

### 분석 화면의 추가 안내 제거·사진과 리포트 정렬

- 사용자 요청에 따라 ‘다른 모습도 궁금하다면’ 안내 영역과 전용 스타일을 제거했다. 사진을 가져가는 기능은 사진 선택 후 보이는 도구 모음의 작은 ‘변화 비교’ 링크로 옮기고 README를 갱신했다.
- 사진 선택·관찰 리포트를 동일한 2열 그리드의 같은 행에 배치해 폭과 높이를 맞추고, 두 카드의 패딩·제목 행 간격을 통일했다. 관찰 설정은 아래의 전체 폭 카드로 옮겼으며, 991px 이하에서는 사진 → 설정 → 리포트 순서로 표시한다. 데스크톱의 긴 리포트는 내용 영역에서 스크롤하며, 분석 완료·실패 시 리포트 위치로 이동한다.
- 검증: 기존 분석·사진 학습·카메라 Node 테스트 23개 통과. 변경된 결과 이동을 반영해 모의 DOM에 스크롤 동작을 추가했다. HTML 중첩·ID·레이블·공통 그리드 배치·사진 도구 모음의 링크를 확인하고, 실제 분석 HTML·CSS·JS의 HTTP 200 응답과 디스크 파일 일치를 점검했다. 실제 브라우저 렌더링은 기존 연결 제한으로 직접 확인하지 못했다.

### 별도 이용 안내 페이지·검색 가능한 FAQ

- 사용자 요청에 따라 메인의 이용 안내를 공개 전용 페이지 `/guide`로 분리했다. 사진 분석·가상 편집·로컬 학습의 사용 순서, 촬영 요령과 파일 규격, 기능별 처리·저장 방식, 자주 묻는 질문 10개로 구성했다. 기존 파란색·화이트 톤과 문어 벡터를 재사용하고, 데스크톱의 옆 목차·작은 화면의 상단 목차와 카드 세로 배치를 적용했다.
- 메인의 기존 긴 안내 섹션을 제거하고 모든 관련 메뉴·소개 링크·학습 가이드 푸터를 새 주소에 연결했다. 분석 화면의 촬영·이용 안내는 `/guide#photo-guide`로 바로 이동한다. 예전 `/#guide` 북마크를 새 페이지로 연결하며 서버·로그인 화면의 안전한 복귀 경로에도 `/guide`를 추가했다.
- FAQ는 질문·답변의 한글·영문을 브라우저에서 검색하며, 공백으로 나눈 검색어의 동시 일치와 문자 정규화를 처리한다. 주제 필터, 결과 수, 빈 결과·초기화, 검색어 지우기, 현재 표시된 답변만 펼치기·접기를 제공한다. JavaScript가 없어도 모든 질문과 답변을 기본 details 요소로 볼 수 있다. 질문별 해시 주소는 필터를 초기화한 뒤 해당 답변을 펼쳐 보여 준다.
- 페이지 목차는 실제 헤더 높이·스크롤 위치·페이지 하단·본문 크기 변경에 따라 현재 항목을 표시하고, 스크롤 처리는 프레임당 한 번으로 제한했다. 목차 상태는 상단의 ‘이용 안내’ 페이지 선택과 구분한다. 검색어는 서버·저장소로 보내지 않고, 안내 화면에는 사진 선택·AI 분석·편집 컨트롤러를 실행하지 않는다.
- 촬영 규격과 사진 처리·저장 설명은 현재 구현을 기준으로 작성했다. 분석 전송 동의, 선택적 리포트·학습 사진 저장, 브라우저의 일회용 사진 전달과 만료 후 정리, 가상 편집·대기 취소의 한계를 구분해 설명했다. 새 라이브러리·외부 서비스·의료 판정 기능은 추가하지 않았다.
- 검증: 관련 Python 테스트 61개와 전체 Node 테스트 93개, 총 154개 통과. 독립 공개 페이지·자산·메뉴·예전 주소·안전한 로그인 복귀, 실제 FAQ HTML을 사용하는 검색·필터·빈 결과·초기화·답변 펼침·질문 주소·목차 상태를 검증했다. HTML 중첩·ID·레이블·ARIA·내부 앵커·자산·아이콘·컨트롤러 요소 연결도 확인했다.
- 현재 프로젝트의 실행 경로·명령·8000/8001 포트 소유권을 확인한 서버만 재시작했다. 실제 이용 안내·기존 기능 페이지·새 JS/CSS의 HTTP 200·디스크 파일 일치·비저장 캐시, 안내 주소로의 로그인 복귀, 웹소켓 비로그인 연결의 401 응답을 확인했다. 실제 사용자 사진·계정·기록을 변경하지 않았으며 AI API를 호출하지 않았다.
- 프로젝트 규칙·디자인 문서와 Sites의 로컬 작업 절차를 적용했다. Computer Use로 화면 확인을 시도했으나 브라우저 목록은 비어 있고 ‘The browser access host is unavailable’ 오류가 반환됐다. 현재 Hairline Lab 창도 발견되지 않아 실제 렌더링·모바일 터치는 직접 검증하지 못했다.

### 분석 페이지 상단 소개 제거

- 요청한 ‘PHOTO ANALYSIS’ 배지, ‘내 헤어라인 살펴보기’ 제목과 소개 문구를 제거했다. 진행 단계 위쪽 여백을 정리하고, 촬영·이용 안내 링크는 기능 영역의 연결 상태 옆으로 옮겼다.
- 기존 ‘사진 분석 공간’을 작은 페이지 제목으로 사용해 제목 구조를 유지했다. 분석·사진 선택·리포트 기능과 별도 변화 미리보기의 소개는 변경하지 않았다.
- 기존 분석 Node 테스트 10개 통과. 소개 영역 제거·페이지 제목·ID·레이블·촬영 안내 링크를 점검하고, 실제 분석 HTML·CSS의 HTTP 200 응답과 파일 일치를 확인했다. 실제 렌더링은 기존 브라우저 연결 제한으로 확인하지 못했다.

### 사용자 제공 MD를 적용한 분석 페이지 컴포넌트 개선

- 사용자 요청에 따라 첨부된 SEED Design 문서를 읽고, 원문을 `docs/references/SEED-Design_사용자제공.md`에 보관했다. 원본과 저장 파일의 해시 일치를 확인했다. 기존 `디자인.md`에 분석 페이지용 `docs/analysis-design.md`를 연결해 공통 규칙과 추가 적용 범위를 구분했다.
- 기존 파랑·중성색·상태색·글꼴을 유지하면서 역할별 표면, 둥근 액션 버튼, 세로 단일 선택 카드, 접이식 보조 항목, 전송·저장 실행 구획을 적용했다. 분석 페이지에만 `static/analysis-theme.css`를 추가하고 모든 스타일을 분석 본문에 한정했다. 공통 헤더·챗봇·다른 페이지의 팔레트·컴포넌트는 변경하지 않았다.
- 단계 표시의 정보 위계와 활성 상태, 파일 첨부·사진 점검·빈 리포트·결과·오류 안내의 간격과 타이포그래피를 정리했다. 주요 분석 행동에만 브랜드 강조를 집중하고 네이티브 라디오·체크박스·details/summary·키보드 포커스를 유지했다. 삭제했던 상단 소개는 다시 넣지 않았으며 같은 크기의 사진·리포트 카드와 문어도 유지했다.
- 분석·촬영·학습 등록·사진 전달·리포트 동작 테스트 23개 통과. HTML 중첩·ID·레이블·선택 항목·SVG 심벌·정적 파일·CSS 변수 연결과 분석 전용 스타일 로드를 점검했다. 주요 텍스트 대비는 기존 WCAG 기준으로 기본 글자 13.37:1, 보조 글자 5.28:1, 파란 버튼의 흰 글자 4.83:1, 약한 파란 배경의 강조 글자 7.61:1을 확인했다. APCA나 전체 SEED 시스템의 완전 구현으로 표현하지 않았다.
- 실제 분석 HTML·새 CSS의 HTTP 200과 디스크 파일 일치를 확인했다. 서버 재시작이나 외부 패키지·API 호출은 필요하지 않았다. Computer Use의 브라우저 접근 호스트가 없어 실제 렌더링·모바일 터치·키보드 화면 검증은 완료하지 못했다.

### 리디 참고 문서 기반 전체 페이지·현행 디자인 MD 교체

- 사용자 요청에 따라 새 리디 디자인 문서의 스타일·컴포넌트·글자·반경·레이아웃·주의 사항을 읽고 전체 화면을 개편했다. 원문을 `docs/references/RIDI_사용자제공.md`에 저장하고 첨부 파일과 해시 일치를 확인했다. 이전 공통·분석 디자인은 이력으로 보관하고, `디자인.md`·`docs/analysis-design.md`를 새 기준으로 교체했다. README와 프로젝트 규칙의 현행 기준도 연결했다.
- 기존 요청의 브랜드 파랑 #0066FF와 Hairline Lab 로고·문어·아이콘을 유지했다. 리디의 흰 바탕, 짙은 글자, 얇은 회색 구분선, 4px 카드, 6px 버튼, 선택 필터와 콘텐츠 중심 배치를 적용했다. 원문의 낮은 대비 블루·작은 터치 치수·미관찰 모바일 상세를 그대로 복제하지 않았고, 외부 로고·표지·구매/대여 개념·폰트 CDN·새 패키지를 추가하지 않았다.
- 메인은 짧은 소개와 사진 분석·가상 비교·학습의 일러스트 기능 카드 3개로 다시 구성했다. 모바일에서는 기능 카드를 가로로 넘겨 선택한다. 예시 이미지는 실제 사용자 분석이나 생성 결과로 표시하지 않는다. 기존 상태 표·내 기록·기능 진입을 유지했다.
- 메인·분석·시뮬레이션·학습·이용 안내·학습 가이드·내 정보·로그인·회원가입의 9개 경로와 기록·카메라·도우미를 같은 규칙으로 맞췄다. 공통 헤더는 브랜드/계정과 메뉴의 2단으로 구성하고 현재 메뉴를 파란 글자·굵기로 표시한다. 사이드 도우미가 열리면 헤더·본문·푸터의 폭을 함께 확장해 시작선을 맞춘다.
- 기존 CSS 11개를 수정했으며 새 전역 테마를 계속 덧붙이지 않았다. 분석 카드의 동일 크기·삭제한 소개·관찰 설정·사진 전달, 편집의 두 비교 방식·동의·저장, 학습 준비 상태·계정별 데이터, 내 정보의 정확한 통계를 유지했다. 높이가 작은 데스크톱 비교 패널에는 내부 스크롤을 제공한다.
- 전체 Node 테스트 93개와 관련 Python 테스트 61개, 총 154개 통과. 임시 DB·계정·워크스페이스 안의 임시 학습 폴더로 9개 경로의 실제 서버 렌더 HTML을 파싱해 제목·중첩·ID·레이블·ARIA·정적 자산·아이콘·CSS 변수 연결을 점검했다. CSS 11개의 문자열·함수·블록 균형도 확인했다.
- 현재 프로젝트의 실행 경로·명령·8000/8001 포트 소유권을 검증한 서버만 재시작해 계정 공통 템플릿을 반영했다. 실제 정적 페이지·학습 가이드·로그인·회원가입·CSS 11개의 HTTP 응답, 파일 일치와 비저장 캐시, 내 정보 로그인 보호와 웹소켓 비로그인 401 응답을 확인했다. 실제 사용자 계정·사진·기록을 변경하거나 AI를 호출하지 않았다.
- 주요 색 대비는 본문/흰색 11.90:1, 보조 글자/정보 면 5.50:1, 흰 글자/브랜드 파랑 4.83:1, 오류 글자/오류 면 5.72:1이었다. 전 화면의 픽셀 대비·실제 모양을 측정했다고 표현하지 않는다.
- Sites의 로컬 개발 절차와 Computer Use의 화면 확인 절차를 적용했다. 브라우저 접근 호스트가 없었으며 Whale 창 연결도 `window id 330210 no longer belongs to Naver_Whale; current owner is Naver_Whale` 오류로 실패했다. 실제 화면·모바일 터치·키보드 렌더링 검증은 완료하지 못했다.

### 분석·변화 미리보기의 상단 문구 제거

- 요청한 변화 미리보기의 ‘CHANGE PREVIEW’·소개 제목·설명, ‘로컬 편집 가능’ 상태와 별도 3단계 표시를 제거했다. 편집 카드부터 시작하도록 여백을 정리하고 더 이상 필요하지 않은 단계·상태 DOM 갱신 코드를 정리했다. 실제 편집 방식 준비 확인과 오류 안내는 유지한다.
- 분석 페이지의 ‘사진 분석 공간’ 제목과 ‘사진을 선택해 시작해 주세요’ 안내를 제거했다. 분석의 기존 진행 단계·연결 상태·촬영 안내는 유지하고, 두 페이지의 페이지 제목은 접근성용으로만 남겼다. 디자인 MD에도 삭제한 소개를 다시 추가하지 않도록 반영했다.
- 기존 분석·편집·사진 학습·카메라 Node 테스트 32개 통과. HTML 중첩·페이지 제목·ID·ARIA/레이블·컨트롤러 연결을 점검하고, 실제 두 페이지와 수정 JS/CSS의 HTTP 200 응답·디스크 파일 일치를 확인했다. 실제 브라우저 화면 확인은 기존 연결 제한으로 완료하지 못했다.

### 분석 페이지를 가로 3열 작업 화면으로 변경

- 요청한 한 화면 구성을 위해 너비 992px·높이 600px 이상에서 사진·관찰 설정·리포트를 가로 3열로 배치했다. 본문·헤더가 화면 너비를 채우고 남은 높이를 카드에 배분한다. 이 조건에서 공통 푸터와 페이지 스크롤을 없애며, 작은 화면과 낮은 창은 기존 세로 흐름을 유지한다.
- 진행 단계·연결 상태·촬영 안내를 한 줄로 줄였다. 전송 동의와 기록 저장은 기본 설정에 남기고, 학습·로컬 분류·모발 영역 확인은 접힌 추가 옵션으로 옮겼다. 사진 점검과 영역 안내는 사진 카드에 모았으며 문어 일러스트와 기존 브랜드 색·컴포넌트 규칙을 유지했다.
- 분석 실행과 리포트 복사·내보내기는 각 카드 하단에 고정했다. 긴 결과·추가 설정·높이가 부족한 사진 영역만 카드 안에서 스크롤하고 키보드 접근을 제공한다. 데스크톱 결과 표시 시 페이지를 자동으로 움직이지 않으며 작은 화면의 결과 이동과 움직임 줄이기 설정은 유지한다. 새 관찰 시 내부 결과 스크롤을 초기화한다.
- 분석 페이지의 도우미는 상단 버튼으로 시작한다. 사용자가 열면 작업 열을 줄이지 않는 떠 있는 패널이며 최소화·대화 복원을 유지한다. 다른 페이지의 기본 사이드바 동작은 유지한다. 추가 옵션의 필수 학습 라벨이 비어 있으면 두 겹의 접힌 항목을 열고 입력으로 포커스를 옮긴다.
- 기존 분석 CSS를 수정해 배치를 관리했으며 새 전역 테마·패키지·서버 API는 추가하지 않았다. 공통 디자인 MD와 분석 디자인 MD를 현행 구조로 갱신했다.
- 전체 Node 기능 테스트 96개 통과. 새 검증은 데스크톱/작은 화면의 결과 이동과 움직임 줄이기, 결과 스크롤 초기화, 접힌 학습 오류의 입력 접근, 도우미의 페이지별 초기 상태·화면 크기 변경·자가 점검 복원을 확인한다. HTML 중첩·ID·레이블·ARIA·컨트롤러 요소·자산·아이콘·명시적 동의·고정 버튼의 DOM 분리와 CSS 블록/함수 균형·토큰 연결을 확인했다.
- 실제 분석 HTML·수정 CSS/JS의 HTTP 200·디스크 파일 일치·비저장 캐시를 확인했다. 서버 재시작과 AI 호출은 필요하지 않았다. Computer Use로 재확인했으나 브라우저 접근 호스트가 없고 Whale 창 연결도 소유권 오류로 실패했다. IDE 미리보기의 접근성 내용은 이전 페이지였고 화면 캡처가 다른 전면 창을 반환해 추가 입력을 중단했다. 실제 데스크톱 치수·모바일 렌더링과 스크롤 유무는 직접 확인하지 못했으며 기능 테스트를 시각 검증으로 표현하지 않는다.

### 나머지 페이지에도 화면을 채우는 가로 배치 적용

- 분석에서 요청한 배치를 메인·변화 미리보기·로컬 학습·이용 안내·학습 가이드·내 정보·로그인·회원가입까지 확대했다. 너비 992px·높이 600px 이상에서 화면 너비와 헤더 아래 높이를 활용하고 공통 푸터·페이지 스크롤을 제거한다. 긴 설정·안내·목록과 높이가 부족한 카드에는 내부 스크롤과 키보드 접근을 제공하며 작은 화면·낮은 창은 일반 문서 흐름으로 돌아온다.
- 메인은 왼쪽 소개·처리 한계와 오른쪽 기능 카드·기술 상태의 격자다. 실제 연결 상태 표를 내부에서 읽으며 기존 기능·기록 진입을 유지한다. 변화 미리보기는 사진·설정·비교 3열로 나누고 실행·오류·이미지 저장을 스크롤 내용과 분리했다. 사진·비교 도움말은 사진 카드 안의 접이식 영역으로 옮겼다. 선택 사진과 도움말을 함께 펼칠 때 겹치지 않도록 사진 영역의 최소 높이도 정했다.
- 로컬 학습은 등록·모델 결과·사진 목록을 3열로 배치했다. 등록·학습·결과 내보내기를 카드 하단에 두고 등록 사진 표를 기본으로 보이게 했다. 파일·라벨·익명 그룹·저장 동의, 실제 수치·모델 상태·삭제·평가 결과 기능과 기존 컨트롤 ID를 유지했다.
- 이용 안내는 고정 목차와 본문 스크롤 패널이다. 목차 스크립트가 데스크톱에서는 본문 패널, 작은 화면에서는 페이지 위치를 추적하도록 바꿨다. 프레임당 갱신 병합·마지막 섹션 판정·FAQ 검색·필터·질문 주소·움직임 줄이기 동작을 유지했다. 학습 가이드는 핵심 답변·실제 준비 상태·상세 안내의 3열이며 준비 상태 버튼과 상세 목차를 읽기 영역에서 분리했다.
- 내 정보는 계정·활동·기본 정보를 나란히 표시하고 새로운 관찰 시작 버튼을 계정 스크롤과 분리했다. 로그인·회원가입은 문어와 소개를 왼쪽, 입력과 제출을 오른쪽에 둔다. 입력·오류 영역이 길면 내부에서 읽고 제출·계정 전환은 접근할 수 있게 했다. CSRF·필수 입력·자동 완성·개인 정보 숨김·안전한 복귀 주소 기능을 변경하지 않았다.
- 도우미가 있는 페이지는 버튼 상태로 시작한다. 가로 배치에서는 상단 메뉴 끝의 버튼·최소화 바로 열며 떠 있는 패널이 본문 열을 줄이지 않는다. 분석의 기존 도구 모음과 작은 화면의 하단 버튼은 유지했다. 최소화·대화 이어가기·자가 점검 기능을 유지한다.
- 공통 배치와 페이지별 열을 기존 CSS 7개에서 관리했다. 새 전역 테마·외부 패키지·서버 API를 추가하지 않았으며 기존 리디 참고 디자인·파랑·글꼴·모서리를 유지했다. 디자인 MD·분석 디자인 MD·README를 현행 구조로 갱신했다.
- Node 기능 테스트 97개와 관련 Python 테스트 61개, 총 158개 통과. 새 기능 검증은 페이지가 움직이지 않아도 안내 본문 패널 스크롤에 맞춰 목차가 갱신되고 FAQ 질문 주소가 열리는지 확인한다. 임시 메모리 DB·계정·워크스페이스 내 임시 학습 폴더로 전체 9개 경로의 실제 렌더 HTML을 점검했다. 중첩·페이지 제목·ID·레이블·ARIA·내부 앵커·자산·SVG 심벌, 원래 컨트롤 ID 보존, CSS 11개의 블록/함수 균형과 공통 변수 연결을 확인했다. 기능 테스트를 실제 렌더링·해상도 측정으로 표현하지 않는다.

### AI 연결 실패의 실행 환경 원인 확인과 복구

- 사용자가 보고한 ‘AI 서비스에 연결할 수 없어요’는 `services/gemini.py`에서 Requests 연결 예외를 처리하는 안내였다. DNS는 정상이고 프록시·별도 인증서 번들은 설정되지 않았으며, 제한된 실행 환경에서 공식 Google HTTPS 요청이 `ConnectionError → MaxRetryError → NewConnectionError → PermissionError(errno=13)`로 실패했다.
- 직전 서버를 AI 작업자의 외부 통신 제한 환경에서 시작한 것이 원인이었다. 승인된 일반 실행 환경의 같은 요청은 Google에 도달했고, 기존 키로 설정된 모델의 메타데이터를 조회하자 HTTP 200과 `generateContent` 지원을 확인했다. 키를 출력하거나 사용자 사진을 보내지 않았으며 분석·이미지 생성 호출도 하지 않았다. 모델 정보 조회는 Google 공식 API 문서를 확인했다.
- 기존 8000/8001 포트의 프로젝트 서버 경로·명령·부모 프로세스를 확인한 뒤, 해당 서버만 종료하고 외부 통신이 가능한 승인된 일반 실행 환경에서 숨김 실행으로 재시작했다. 현재 HTTP·웹소켓 리스너와 `/api/status`의 HTTP 200·분석 키 설정 상태를 확인했다. 인증키·사용자 계정·사진·기록·애플리케이션 코드·시스템 보안 설정은 변경하지 않았다.
- README에 서버 실행 환경의 외부 통신 권한, 키 설정 상태와 실제 연결 확인의 차이, 사진 없이 모델 정보를 조회하는 진단 방법을 기록했다. 실제 사용자 사진의 재분석 성공 여부는 사용자의 다음 분석 실행으로 확인해야 한다.

- 추천 테스트 9개 및 실제 분석 DOM의 표시·초기화 검증을 추가해 전체 Node 기능 테스트 109개가 통과했다. 새 JS/기존 app.js 구문, HTML 중첩·ID·ARIA·숨김 기본값·자산·추천의 내부 스크롤 배치, CSS 균형·변수 연결을 확인했다. 실제 localhost의 분석 HTML·JS·CSS가 HTTP 200이며 디스크 파일과 일치했다.
- 서버를 재시작하거나 실제 AI·사용자 위치·사용자 사진을 호출하지 않았다. 브라우저 연결 오류로 실제 렌더링·위치 권한 창·외부 지도 검색 결과는 직접 검증하지 못했다. 위치 관련 동작은 모의 응답으로 검증했다.

### Gemini 요청 실패 진단·일시 오류 복구

- 사용자가 보고한 ‘AI 서비스가 요청을 완료하지 못했어요’는 키/권한·할당량·모델 오류 외의 모든 비정상 HTTP 응답을 같은 문구로 처리하던 분기다. 원래 실패의 Google HTTP 상태가 기록되지 않아 당시 원인은 확정하지 못했다. 현재 실행 중인 서버의 키·모델이 설정 파일과 같음을 값 노출 없이 확인했다.
- 외부 통신이 가능한 환경에서 기존 키와 `gemini-2.5-flash`의 모델 조회와 사진 없는 구조화 텍스트 생성이 각각 HTTP 200으로 응답했다. 실제 로컬 분석 API에도 프로그램으로 만든 단색 정사각형을 전송해 Google 응답과 정상적인 `photo_not_usable` 422 거절까지 확인했다. 이 시점에는 기존 오류가 재현되지 않았다. 사용자 사진·의료 기록은 진단에 사용하지 않았다.
- 사진 분석의 HTTP 500·502·503·504만 기본 1초·2초 간격으로 최대 2회 추가 시도한다. `Retry-After`와 남은 대기 시간을 반영해 장시간 대기나 무제한 반복을 피한다. 키·권한·할당량·잘못된 요청·모델 오류, 응답 여부가 불확실한 연결 오류/타임아웃, 유료 이미지 생성은 자동 반복하지 않는다.
- 일시 서비스 오류, HTTP 400 요청 설정, 프로젝트 이용 조건, 만료·잘못된 키를 구분한 안내를 추가했다. 서버에는 HTTP 상태와 시도 횟수만 남기고 Google 오류 본문·API 키·사진·프로젝트 식별자를 출력하지 않는다. 프롬프트·모델·요금 설정·저장 동의·사용자 데이터는 바꾸지 않았다. README에 동작과 공식 오류 문서를 연결했다.
- Gemini 복구 단위 테스트 12개와 애플리케이션 테스트 39개, 총 51개가 통과했다. 성공 복구·재시도 상한·대기 예산·Retry-After·권한/할당량 비반복·유료 생성 비반복·잘못된 AI 출력·민감 정보 비노출을 확인했고 모의 Google 오류를 사용한 실제 Flask 요청도 검증했다.
- 8000/8001 리스너·작업 경로·명령·부모 관계를 확인한 프로젝트 서버만 종료하고, 외부 통신 가능한 승인된 환경에서 숨김 재시작했다. 새 프로세스의 두 포트·상태 API 200과 단색 이미지의 정상 거절 응답을 다시 확인했다. 기존 오류의 원인이나 실제 사용자 사진의 분석 성공을 확정한 것으로 표현하지 않는다.

### 병원 찾기·약 안내의 전용 모달 분리

- 리포트 본문의 접이식 추천 내용을 독립된 네이티브 dialog로 옮겼다. 리포트에는 ‘병원 찾기 / 약·치료제 안내’ 버튼만 남기고 각각의 탭을 바로 연다. 분석 전에는 진입 버튼을 숨기며 저장 리포트에도 같은 동작을 제공한다.

- 기존 추천 규칙·지도 검색 범위·일반 약 안내·외부 전송/저장 경계를 유지했다. 모달 스타일을 `static/recommendations-dialog.css`로 분리하고 본문 안의 이전 추천 스타일을 제거했다. 공통/분석 디자인, 추천 로직과 README를 현재 화면으로 갱신했다.
- 모달 진입·선택 탭·키보드 전환·포커스 복귀·Esc·배경 클릭·닫힌 상태의 위치 차단·늦은 이벤트 폐기와 실제 분석 DOM의 계정 변경을 검증해 전체 Node 기능 테스트 116개가 통과했다. JavaScript 구문, HTML 중첩·고유 ID·ARIA·탭 연결·숨김 기본값, CSS 균형·공통 변수, SVG 심벌 참조를 확인했다. 실제 localhost의 분석 HTML·JS·CSS·아이콘 응답이 200이고 작업 파일과 일치했다.

### Gemini 호출 한도 시 로컬 Ollama 자동 전환

- 사진 분석 경로에 `AnalysisService`와 `OllamaClient`를 연결했다. Gemini가 HTTP 429(`upstream_quota`)를 반환할 때만 같은 사진·관찰 부위·동의한 보조 데이터로 로컬 비전 관찰을 한 번 시도한다. 새 요청은 다시 Gemini부터 시작한다. 키·권한·연결·시간 초과·응답 형식·사진 관찰 불가 오류나 유료 이미지 생성은 자동 전환하지 않는다.
- Ollama의 `/api/show`로 비전 기능과 로컬 모델 여부를 확인한 후 `/api/chat`에 base64 JPEG와 JSON Schema·기존 관찰 지시를 전송한다. Gemini의 대문자 스키마 타입을 표준 JSON Schema 타입으로 변환하고 동일한 결과 검증을 적용한다. 텍스트 전용·미설치·cloud 모델은 사진 요청 전에 거부하고 미완성 결과를 임의로 보완하지 않는다.
- 설정은 기본 활성화, `http://127.0.0.1:11434`, `qwen2.5vl:3b`, 120초다. 서버 전용 `.env.example`과 `docs/Ollama_자동전환.md`에 준비·변경·오류 처리와 공식 API 근거를 정리했다. 기존 `.env`·키·요금·사용자 자료는 변경하지 않았고 모델도 자동 다운로드하지 않았다.
- 루프백 주소만 허용하며 로컬 접속의 환경 프록시·netrc·리다이렉트를 끈다. 원격 모델 메타데이터를 거부하고 Gemini 키를 Ollama에 보내지 않는다. 원본 사진·프롬프트·오류 응답 본문을 새 로그에 출력하지 않는다. Google를 먼저 호출하므로 기존 전송 동의는 유지한다.
- 결과·선택 저장 기록에 실제 `provider`·`model`·`fallback_reason`을 넣고 화면에 로컬 전환을 표시한다. 기존 기록도 계속 열 수 있다. 상태 API의 로컬 설정은 추론 준비 완료로 표시하지 않으며 Gemini+Ollama 대기 시간을 브라우저에 전달한다. 기본 브라우저 대기는 200초다. 분석 동의 설명과 이용 안내에도 전환 흐름을 반영했다.
- 새 Python 테스트 14개와 분석 화면 테스트를 추가했다. 전체 Python 158개·Node 116개, 총 274개가 통과했다. 모의 Gemini 429에서 로컬 네이티브 요청·동의·실제 사용 모델의 저장, 전환 제외·로컬 실패·텍스트 전용·cloud/주소 차단·JSON·대기 예산·늦은 상태와 기존 기능을 검증했다. JavaScript/Python 구문과 HTML ID·ARIA·자산 연결도 확인했다.

Gemini 한도만 모의로 발생시킨 Flask 요청도 실제 Ollama까지 연결되고 설치 명령을 포함한 503을 반환했다. 실제 비전 추론 성공·관찰 정확도·사용자 사진의 분석을 검증한 것은 아니다.

### 비전 모델 QLoRA 학습 기능

- `/training/vision`에 사진·정답 설명·학습 결과의 가로 3열 화면을 추가하고 기존 로컬 분류기 페이지에서 연결했다. 사진·익명 그룹·관찰 부위·관찰 JSON을 직접 입력해 저장하며, 기존 기준/의심 라벨이나 AI 응답을 정답으로 자동 사용하지 않는다. 저장 동의·수정·삭제·준비 상태·학습 스텝·학습 취소·모델 테스트·LoRA ZIP·내 분석 적용을 제공한다.
- 웹앱의 `.venv`와 분리한 `.venv-vlm`에 CUDA 학습 환경을 설치했다. 공개 Qwen2.5-VL-3B-Instruct 기본 가중치 약 7.5GB를 `models/vlm-base`에 준비하고 revision `66285546d2b821cf421d4f5eb2576359d3770cd3`를 고정했다. 기존 Ollama GGUF·키·요금 설정·사용자 사진·사용자 모델은 덮어쓰지 않았다. 학습·추론은 오프라인·Safetensors·원격 코드 미실행을 적용한다.
- Windows 애플리케이션 제어가 torchvision 확장 로드를 WinError 4551로 차단했다. 보안 설정을 바꾸지 않고 해당 의존성을 제거한 뒤 사진 전용 Pillow 처리기가 있는 Transformers 4.51.3·PEFT 0.15.2 조합을 확인했다. 최종 환경은 PyTorch 2.8.0+cu126·bitsandbytes 0.49.2이며 전체 버전은 `requirements-vlm-lock.txt`에 기록했다.
- 실제 QLoRA는 NF4 4비트·rank 8·배치 1·누적 2·gradient checkpointing을 사용한다. 시스템·사용자·이미지 토큰을 손실에서 제외하고 정답 부분만 학습한다. 관찰 가능/불가 각각 4장 이상·익명 그룹 4개와 두 상태가 포함되는 그룹 분리를 확인한다. GPU 작업을 직렬화하고 앱의 기본 Ollama를 해제한 뒤 실행한다. 계정 경계·CSRF·파일 경로·예시 형식·최대 스텝을 검증하며 실패·취소를 완료로 표시하지 않는다.
- 1스텝 smoke에서 워밍업 때문에 실제 가중치가 바뀌지 않는 경우를 확인해 20스텝 미만은 워밍업을 사용하지 않도록 수정했다. LoRA B 가중치가 갱신됐는지 확인한 경우만 완료로 저장한다. 최종 합성 예시 학습에서 학습 가능 매개변수 1,843,200개, 1 optimizer 스텝, 학습 손실 1.1477·보류 손실 2.2416과 약 7.4MB 어댑터 저장을 확인했다. 수치는 합성 비의료 fixture의 동작 확인이며 실제 관찰 정확도 개선을 의미하지 않는다.
- 학습 모델의 응답에서 JSON 시작·종료 형식 문제를 확인했다. 출력 제약 라이브러리 실험은 최종 경로에서 제거하고 객체의 시작 구문만 미리 제공하는 방식으로 실제 모델 응답을 확인했다. 모든 관찰 값은 모델이 생성하며 JSON·관찰 규격을 다시 검사한다. 불완전 응답을 가짜 관찰로 보완하지 않는다. 최종 직접 추론은 45.2초에 규격화 응답을 반환했다.
- 적용 모델은 본인 계정의 설정으로만 저장한다. Gemini 429일 때 본인의 어댑터를 별도 로컬 프로세스로 사용하고 실제 provider/model을 리포트에 표시한다. 적용을 해제하면 기존 Ollama로 돌아간다. 임시 메모리 DB의 격리 계정에서 실제 어댑터 적용 → 모의 Google 한도 → 실제 GPU 추론 → HTTP 200/local_adapter → 비공개 ZIP 200을 35.9초에 확인했다. Google 호출과 리포트 저장은 0회이며 실제 사용자 사진을 사용하지 않았다.
- 신규 Python 11개·Node 5개를 포함해 전체 Python 169개·Node 120개, 총 289개가 통과했다. 자료 수정 시 JPEG 재인코딩으로 ID가 달라지는 문제와 계정 변경 뒤 지연 응답이 화면을 복구하는 경우를 방어했다. 로그인 복귀·동의·개인 사진 접근·다른 계정 모델 차단·GPU 작업·취소·JSON 표준 입력·내보내기를 검증했다.

### 이마·헤어라인 사진 인식 개선

- 사용자가 ‘OCR’의 의미를 이마·헤어라인 사진 인식으로 명확히 해 사진 분석 경로만 개선했다. 문자 OCR 서비스와 모델은 변경하지 않았다.

### 병원 찾기 모달 디자인 수정
