# 로컬 비전 모델 학습

`/training/vision`에서 사진과 직접 확인한 관찰 정답으로 **Qwen2.5-VL-3B-Instruct의 LoRA 가중치**를 학습한다. 기존 `/training`의 HOG·SVM 분류기는 별도 기능으로 유지한다.

Ollama에 설치된 압축 GGUF를 바로 학습하지 않는다. 같은 Qwen의 공개 Hugging Face 가중치를 4비트로 불러와 QLoRA를 수행하고, 완료한 어댑터를 별도 로컬 GPU 프로세스로 실행한다. Ollama 모델 파일이나 모든 계정의 기본 모델을 덮어쓰지 않는다.

## 사용 흐름

1. `/training/vision`에 직접 접속해 로그인한다. `/training`은 사진 분류기 학습 전용이며 비전 학습 이동 버튼은 표시하지 않는다.
2. 사용 권한이 있는 사진을 선택하고 익명 그룹 코드·관찰 부위를 지정한다. 같은 사람의 사진은 같은 코드를 사용한다.
3. 관찰 가능 여부·두피 노출·요약·부위별 관찰·사진 한계·다음 행동을 직접 확인해 입력하고 학습용 저장에 동의한다. 관찰 불가 예시는 `image_usable=false`, `visible_signal=unclear`, 빈 관찰 목록을 사용한다.
4. 관찰 가능·불가 예시 각각 4장 이상, 전체 그룹 4개 이상을 준비한다. 두 상태가 학습·검증 모두에 포함되는 그룹 분리가 가능해야 한다. 이 수는 기능 시작을 위한 프로젝트 규칙이며 충분한 학습 품질을 보장하는 기준이 아니다.
5. 학습 스텝을 선택하고 **QLoRA 학습 시작**을 누른다. 진행 단계·스텝·학습 손실과 완료 후 검증 손실을 확인한다. 자동으로 학습하지 않는다.
6. 완료 모델의 **선택 사진 테스트**로 현재 선택한 사진을 로컬에서 관찰한다. **내 분석에 적용**을 누르면 본인 계정의 Gemini 한도(429) 발생 시 해당 모델을 사용한다. **기본 Ollama로**를 누르면 적용을 해제한다.

완료 모델은 자동 적용하지 않는다. LoRA ZIP은 어댑터 가중치·설정·학습 메타데이터만 포함하며 사진과 정답 예시는 포함하지 않는다. 사용자 라벨·기존 SVM 결과나 AI 답변을 관찰 정답으로 자동 바꾸어 사용하지 않는다. 의료 진단·단계·확률·약 처방을 학습 목표로 제공하지 않는다.

## 설치

기존 웹앱의 `.venv`와 분리한 `.venv-vlm`을 사용한다. Windows Python 3.12, NVIDIA CUDA GPU에서 다음을 실행한다.

```powershell
powershell -File scripts/setup_vlm.ps1
```

설치 스크립트는 CUDA PyTorch·PEFT·bitsandbytes·Transformers를 설치하고 공개 기본 가중치를 `models/vlm-base`로 내려받는다. 모델을 내려받을 때는 인터넷이 필요하며 학습 사진은 전송하지 않는다. 모델의 최초 다운로드 revision을 `hairline-base.json`에 고정한다. 학습·추론은 `local_files_only`, 오프라인 모드, Safetensors와 `trust_remote_code=false`를 사용한다.

현재 기본 가중치 revision은 `66285546d2b821cf421d4f5eb2576359d3770cd3`이다. 확인한 환경은 PyTorch 2.8.0+cu126, Transformers 4.51.3, PEFT 0.15.2, bitsandbytes 0.49.2이며 전체 패키지는 `requirements-vlm-lock.txt`에 기록한다. 사진 전용 Pillow 처리기를 사용하므로 torchvision C++ 확장은 필요하지 않다. Windows에서 해당 확장이 차단된 경우 보안 설정을 변경하지 않고 설치 의존성에서 제외한다.

## 학습 방식

- 고정 기본 모델: [Qwen/Qwen2.5-VL-3B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct).
- NF4 4비트·이중 양자화, 지원 GPU에서 bfloat16, 배치 1·gradient accumulation 2·gradient checkpointing.
- 언어 영역의 `q_proj`, `v_proj`에 rank 8·alpha 16 LoRA를 적용한다. 시각 인코더와 기존 기본 가중치는 학습 대상이 아니다.
- 정답을 제외한 시스템·사용자·이미지 토큰은 손실 계산에서 제외한다. 2,048 토큰을 초과한 예시는 자동 잘라내지 않고 문장 축약을 안내한다.
- 학습률 2e-4, 최대 200 optimizer 스텝. 20스텝 미만은 워밍업을 사용하지 않아 1스텝에서도 실제 갱신을 확인할 수 있다.
- LoRA B 가중치가 실제로 변한 경우에만 완료 모델로 저장한다. 취소·비정상 손실·GPU 메모리 부족·환경 오류는 완료로 표시하지 않는다.
- 그룹을 먼저 분리하고 고정 seed 42로 실행한다. 검증 손실은 정답 문장의 토큰 예측 손실이며 의료 정확도·치료 효과·독립된 임상 평가가 아니다.

## 상태·계정·파일

API는 `/api/training/vision/` 아래의 `status`, `photo/<id>`, `save`, `remove`, `start`, `cancel`, `activate`, `test`, `export/<job>`다. 로그인과 변경 요청의 CSRF 검사를 적용하며 본인 계정 자료만 접근한다. 경로·사진 ID·작업 ID·정답 형식·스텝 범위를 검증한다.

`data/vision-training/users/<계정 ID>/`에 정답 목록·메타데이터를 제거한 JPEG·학습별 고정 복사본·어댑터·적용 설정을 보관한다. 사용자 사진과 모델은 Git에서 제외한다. 등록 예시를 삭제해도 이전 학습 복사본이나 학습 가중치에서 해당 내용을 제거하는 작업은 아니다. 모델을 해제하면 분석에서 사용하지 않는다.

GPU 작업은 앱 내부 동시 실행 제한과 OS 파일 잠금으로 직렬화한다. 이 앱의 기본 Ollama 모델을 해제한 뒤 학습·어댑터 테스트를 시작해 GPU 메모리를 확보한다. 다른 계정이 GPU를 쓰는 경우 계정 ID나 데이터를 노출하지 않고 대기 안내를 반환한다. 취소는 요청한 계정의 작업에만 적용하며 관리 중인 자체 프로세스만 종료한다. 서버 재시작 전의 작업은 취소 표식을 확인한 다음 학습 단계에서 중단할 수 있다.

계정 변경은 화면의 사진·정답·모델·테스트 결과를 지우고 지연 응답을 무시한다. 모델 테스트는 사진과 결과를 저장하지 않는다. Gemini 한도로 학습 모델에 전환한 리포트는 실제 `provider=local_adapter`·모델 ID를 표시하고, 저장을 선택한 경우만 기록에 포함한다.

## 검증 범위

합성 단색 이미지와 비의료 정답으로 1 optimizer 스텝을 실행하는 별도 smoke fixture를 `.cache/vlm-smoke`에 만든다. 사용자 데이터셋에 추가하거나 본인 분석 모델로 자동 적용하지 않는다. 실제 가중치 갱신·보류 손실·어댑터 저장은 실행 결과로 확인하고, 실제 사진의 관찰 정확도 개선은 주장하지 않는다.

2026-10-30 RTX 4070 Laptop 8GB에서 실제 1스텝·학습 가능 매개변수 1,843,200개·LoRA B 가중치 갱신·약 7.4MB 어댑터 저장을 확인했다. 별도 메모리 DB의 격리 계정에서 실제 모델 적용·Gemini 한도 모의·로컬 GPU 추론·HTTP 200/local_adapter·비공개 ZIP을 확인했으며 Google 호출·실제 사용자 사진·리포트 저장은 사용하지 않았다. 이 합성 단색 입력도 유효 사진으로 응답할 수 있어 사진 적합성이나 의료 정확성의 검증으로 취급하지 않는다.

관찰 요청에 JSON 스키마를 포함하고 객체의 시작 구문만 미리 제공한다. 모든 관찰 값은 모델이 생성하며, 반환 후 JSON과 기존 관찰 규격을 다시 검증한다. 불완전하거나 규격에 맞지 않은 모델 응답은 임의의 관찰로 채우지 않는다. 파일 저장 성공과 관찰 모델의 품질은 구분한다.

## 구현 및 공식 자료

`services/vlm_data.py`는 자료·그룹 분리·잠금, `services/vision_training.py`는 작업·취소·계정 적용, `scripts/vlm_worker.py`는 실제 학습과 추론을 맡는다. 웹 서버가 GPU 라이브러리를 직접 import하지 않는다.
