# 페이지 전환·스켈레톤 UI

홈, 사진 분석, 변화 미리보기, 로컬 분류기 학습, 비전 모델 학습, 이용 안내, 학습 가이드, 내 정보, 로그인, 회원가입의 10개 경로에 공통 이동 효과와 초기 로딩 표시를 적용한다. 기존 색·가로 작업 배치·화면별 기능은 유지한다.

## 표시 방식

- 지원 브라우저의 같은 출처 페이지 이동에는 Cross-document View Transitions를 사용한다. 본문은 130ms에 사라지고 220ms에 나타나며 이동 거리는 4~6px이다. 지원하지 않는 환경에서도 본문 진입 효과를 제공한다. 링크 클릭·폼 제출·주소·뒤로 가기를 가로채지 않는다.
- 페이지의 실제 열 구성에 맞춘 회색 스켈레톤을 초기 준비 중 표시한다. 홈은 왼쪽 촬영 준비·가운데 요약 3개와 기록·오른쪽 안내의 3단 구조, 분석·비교·학습은 3열, 안내·계정·내 정보는 2열을 사용한다. 작은 창에서는 홈의 오른쪽 안내를 가운데 기록 아래로 옮기고 620px 이하에서는 1열이 된다.
- 인증, 초기 상태, 저장 리포트, 전달받은 사진 등 실제 시작 작업을 `HairlinePage.track(promise)`로 추적한다. DOM과 추적한 작업이 준비되면 다음 프레임에 표시한다. 최소 대기 시간이나 추가 API 요청은 없다. 이후 업로드·저장·주기적 갱신에는 전체 페이지 스켈레톤을 다시 표시하지 않는다.
- 사진 관찰 중에는 리포트 모양을, 이미지 편집 중에는 원본·결과 모양을 표시한다. 기존 대기 문구·취소 버튼·오류 처리를 유지한다. 기록 목록의 기존 스켈레톤에도 같은 반짝임을 적용한다.

## 복구·접근성

스켈레톤 장식은 `aria-hidden`으로 숨기고 실제 준비 상태는 `aria-busy`와 별도 상태 문구로 전달한다. 준비 전 본문은 `visibility: hidden`으로 배치를 유지한다. 헤더는 계속 조작할 수 있다. JavaScript가 실행되지 않으면 본문이 기본 표시된다.

요청 성공·실패 모두 표시를 해제하고 기존 호출자가 결과를 처리한다. 시작 작업이 멈춘 경우에는 6.5초 후 본문을 열어 해당 페이지의 상태·오류·복구 동작을 사용할 수 있게 한다. BFCache 복귀 때도 표시를 해제하고 뒤늦은 응답이 전체 화면을 다시 가리지 못하게 한다. `prefers-reduced-motion: reduce`이면 페이지 이동·진입·스켈레톤 반짝임을 끈다.

## 관리 파일과 검증

공통 코드는 `static/page-experience.js`·`static/page-experience.css`다. 각 HTML의 head에서 공통 스타일 다음에 classic script를 먼저 로드하며, `main[data-page-content]` 안에 장식용 스켈레톤을 둔다. 초기 요청 추적은 기존 페이지 스크립트에서 연결한다. 새 외부 의존성·저장소·개인정보 전송은 추가하지 않는다.

`tests/page-experience.test.cjs`의 7개 테스트로 DOM·연속된 초기 요청·성공/실패·타임아웃·기존 busy 상태 복원·뒤로 가기·움직임 줄이기·이동 비간섭을 확인했다. 기존 Node 테스트 120개와 Flask 애플리케이션 테스트 39개도 통과했다. 별도 메모리 DB에서 10개 경로의 HTML 중첩·고유 ID·ARIA·정적 자산·공통 연결과 CSS 변수·괄호를 검사했다. 서버 재시작 후 공개 페이지 9개와 정적 자산·HTML 15개의 실제 HTTP 응답도 확인했다. 내 정보는 격리 계정으로 구성과 실제 서버의 로그인 보호를 각각 확인했다. 실제 브라우저 렌더링은 CUA의 Node 런타임 시작 오류로 직접 확인하지 못했다.

참고: [Chrome의 Cross-document View Transitions 문서](https://developer.chrome.com/docs/web-platform/view-transitions/cross-document), [MDN의 pagereveal 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Window/pagereveal_event).
