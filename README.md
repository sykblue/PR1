# Hairline Lab

사진에서 헤어라인·두피 노출을 관찰하고, 가상의 모발 변화를 비교하는 로컬 웹앱입니다. 사용자 제공 리디 디자인 문서를 바탕으로 전체 화면을 정리한 [디자인.md](./디자인.md)와 개발자 관점의 [스킬 규칙.md](<./스킬 규칙.md>)를 적용했습니다. 기존 브랜드 파랑 #0066FF를 유지합니다.

## 바로 실행

이 작업 폴더에는 Python 3.12 가상환경과 모발 분할 모델이 준비되어 있습니다. PowerShell에서 실행하세요.

```powershell
.\.venv\Scripts\python.exe app.py
```

브라우저에서 **http://127.0.0.1:8000** 으로 접속합니다. VS Code Live Server는 Python API를 실행하지 않으므로 `index.html`을 직접 열거나 Live Server 주소로 접속하면 분석 기능이 작동하지 않습니다. 서버를 종료하려면 실행 터미널에서 Ctrl+C를 누릅니다.

## 전체 페이지 디자인

현재 기준은 [디자인.md](./디자인.md), 전체 구성의 원문 참고 자료는 [리디 디자인 문서](docs/references/RIDI_사용자제공.md)입니다. 버튼·입력·선택 컨트롤은 추가 요청한 [One UI 세부 요소 기준](docs/control-design.md)을 적용합니다. 이전 공통·분석 디자인 기준은 참고 이력으로 보관합니다.

- 메인 본문 맨 위에는 사진 준비 도우미와 학습 가이드/내 정보 바로가기를 표시합니다. 그 아래에는 기능 캐러셀·가상 광고 배너·촬영/결과/데이터 정보 카드가 이어집니다. 분석·비교·학습 카드 3개는 기능명 선택 버튼·좌우 버튼·스와이프·키보드로 넘길 수 있으며 데스크톱 높이는 312px입니다. 좁은 모바일에서는 일러스트와 설명을 위아래로 배치합니다. 준비 체크는 브라우저 안에서만 처리하며 광고는 실제 제휴 광고가 아닌 디자인 예시로 표시합니다.
- 메인과 모든 서브 페이지는 상단 중앙 로고·가운데 메뉴를 공유합니다. 로고 아이콘·BETA 배지는 표시하지 않으며 로그인·회원가입도 같은 메뉴와 기존 복귀 링크를 사용합니다. 헤더는 데스크톱 144px, 991px 이하 168px이고 로고는 48/40/36px입니다. 공통 스타일은 `static/styles.css`에서 관리합니다.
- 모든 기능 페이지는 흰 바탕, 짙은 글자, 기존 4px 작업 카드를 유지합니다. 버튼은 18px, 입력·선택은 12px 모서리로 맞췄으며 파랑·중립색 표면과 눌림·포커스·비활성 상태를 사용합니다. 메인 시작 표시도 공통 주요 버튼 스타일을 사용하며 기능별 본문 배치는 유지합니다.
- 분석·편집·학습·이용 안내·학습 가이드·내 정보·로그인·회원가입과 기록·카메라·도우미의 형태를 맞췄습니다. 데이터·동의·인증·분석 기능은 유지합니다.
- 너비 992px·높이 600px 이상에서는 페이지를 화면 너비·높이에 맞춥니다. 분석·편집·학습은 가로 3열, 안내는 목차와 읽기 영역, 계정 화면은 소개와 입력 영역으로 나눕니다. 긴 내용과 목록은 영역 안에서 스크롤하며 주요 실행·저장·제출 버튼은 고정합니다. 작은 화면과 낮은 창은 일반 세로 흐름을 유지합니다.
- 글꼴은 기존 Pretendard·시스템 스택을 사용하고 외부 브랜드 로고·표지·패키지를 도입하지 않습니다. 실제 화면 검증 여부는 [개발 기록](<docs/개발 기록.md>)에 구분해 기록합니다.
- 홈부터 로그인·회원가입까지 전체 10개 경로에 짧은 본문 전환과 페이지별 스켈레톤을 적용했습니다. 실제 초기 데이터 준비에 맞춰 표시하며 분석·이미지 편집 대기 상태에도 스켈레톤을 사용합니다. 움직임 줄이기 설정과 오류·뒤로 가기 복구는 [페이지 전환·로딩](docs/페이지_전환_로딩.md)에 정리했습니다.

## 별도 사진 분석 페이지

상단 **사진 분석** 또는 메인 화면의 **사진 분석 시작**을 누르면 **http://127.0.0.1:8000/analysis** 로 이동합니다. 사진 선택·촬영·분석 결과는 분석 페이지에서 확인하며, 가상 편집은 별도 변화 미리보기 페이지를 제공합니다.

1. **사진 준비:** 파일을 업로드하거나 카메라로 촬영합니다. 선택한 사진의 크기와 전체 밝기를 브라우저에서 점검합니다. 이 점검은 촬영 도움말이며 모발 선명도·의학적 품질 점수가 아니고, 분석을 자동 실행하거나 사진을 외부로 보내지 않습니다.
2. **관찰 설정:** 전체·헤어라인·정수리/가르마·모발 분포 중 원하는 부위를 고르고 전송·저장 항목을 확인합니다. 선택한 부위는 서버 검증 후 AI 관찰 프롬프트에 반영하며, 사진에 없는 부위를 추측하거나 실제 밀도·모낭 수를 산출하지 않습니다.
3. **리포트 확인:** 부위별 관찰·사진의 한계·다음 행동을 확인하고 내용 복사, 텍스트 저장 또는 기존 JSON 리포트 저장을 사용할 수 있습니다. 작은 화면에서는 분석 완료 시 결과로 이동합니다. 부위를 바꾸거나 사진을 지우면 이전 리포트를 초기화합니다.

리포트의 **병원 찾기 / 약·치료제 안내** 버튼은 최대 800px의 진료 안내 모달에서 해당 탭을 엽니다. **내 주변 병원 보기**를 누르면 현재 위치를 확인하고 두 번째 모달에 가까운 병원 목록·주소·전화·등록 운영 시간을 표시합니다. 소수 셋째 자리의 위치로 같은 서버의 [심평원 공개 자료](docs/병원_데이터.md)를 검색하며 위치를 저장하거나 외부 지도에 보내지 않습니다. 자료는 2026-09-30 기준 피부과 전문의 신고기관 1,744곳이며 실제 운영·진료 여부는 방문 전에 확인해야 합니다. 약 탭의 기존 소개 사진 3개와 공통 출처·상담 블록을 제거하고 제품 20개 각각에 실제 사진을 연결했습니다. 제품 포장 사진 19개·실제 낱알 식별 사진 1개이며, 이미지를 누르면 크게 볼 수 있고 각 카드에 사진 출처를 표시합니다. 목록은 2열·600px 이하 1열입니다. [제품별 사진 출처](docs/의약품_제품사진.md)에 정리했습니다. 두 모달은 닫기·Esc·배경 클릭·포커스 복귀와 키보드 조작을 지원합니다. 요청 검증·상태 초기화는 [추천 로직](docs/추천_로직.md)을 따릅니다.

분석 페이지에서 사진을 선택한 뒤 사진 도구 모음의 **변화 비교**를 누르면 선택한 원본을 새 편집 페이지로 가져갑니다. 이 버튼을 누를 때만 브라우저 IndexedDB에 사진 한 장을 임시 보관하고, 무작위 일회용 키로 전달한 뒤 읽는 즉시 삭제합니다. 5분이 지난 전달은 거절하고 다음 접근 때 정리하며, 로그인 계정이 달라진 경우에도 읽지 않고 삭제합니다. 일반 메뉴 이동은 사진을 가져가지 않습니다. 서버에 전달용 사진을 저장하지 않습니다.

메인 **내 기록**에서 리포트를 선택하면 `/analysis?report=<기록 ID>`로 이동해 본인 계정의 저장된 리포트를 불러옵니다. 이때 AI를 다시 호출하지 않고 원본 사진을 복원하지 않습니다. 비로그인 상태는 로그인 후 분석 주소로 돌아옵니다. 기존 `/#analysis`는 분석 페이지로, `/#simulation`·`/analysis#simulation`은 변화 미리보기 페이지로 연결합니다.

## 별도 변화 미리보기 페이지

상단 **변화 미리보기**는 **http://127.0.0.1:8000/simulation** 으로 이동합니다. 사진 선택·카메라 촬영 → 부위와 강도·편집 방식 선택 → 원본과 비교·PNG 저장 순서로 사용합니다.

- 헤어라인·정수리·모발 분포, 1~100의 편집 강도와 빠른 선택을 제공합니다. 강도는 편집 설정이며 탈모 비율이 아닙니다.
- 슬라이더와 나란히 비교를 전환할 수 있습니다. 사진·부위·강도·편집 방식을 바꾸면 이전 결과를 지웁니다. 저장 이미지에는 가상 편집 안내를 포함합니다.
- 실제 서버 설정에 따라 사용 가능한 방식을 표시합니다. 기본 로컬 합성은 모발 분할 모델과 OpenCV가 필요하고, 로컬 AI는 별도 설정이 필요합니다. Google 유료 편집은 별도의 사진 전송·비용 확인을 모두 선택해야 실행합니다. 자동 생성이나 자동 재시도는 하지 않습니다.
- 대기 취소는 브라우저의 응답 대기를 중단합니다. 서버에서 시작한 처리는 계속될 수 있으며 유료 요청 비용이 취소되는 기능은 아닙니다.
- 사진과 편집 결과는 계정 기록에 저장하지 않습니다. 계정 변경 시 현재 사진·동의·결과를 지우고 이전 요청의 늦은 응답을 표시하지 않습니다.

관찰 프롬프트 버전은 `hair-observation-v5-scalp-reference`입니다. 이마 피부와 모발 영역 안의 두피 노출, 선택 부위의 가림과 조명·각도 영향을 별도로 기록합니다. 근거가 충돌하거나 부위가 충분히 보이지 않으면 판단을 보류하며, 이마 높이·M자 형태만으로 선천적 헤어라인과 탈모를 구분하지 않습니다. 사진 분석은 최대 2048px·JPEG 품질 95로 처리하고 단색 입력은 AI 호출 전에 거절합니다. 기존 관찰 정책은 [사진 관찰 고도화](docs/사진_관찰_고도화.md), 확대 두피 참고 모델은 [공통 두피 학습 모델](docs/공통_두피_학습_모델.md)에 정리했습니다. 실제 사진의 임상 성능이나 이전 버전 대비 일반 헤어라인 정확도 향상을 측정한 것은 아닙니다.

## 별도 이용 안내 페이지

상단 **이용 안내**는 **http://127.0.0.1:8000/guide** 로 이동합니다. 로그인 없이 사용 순서, 촬영 규격, 기능별 사진 처리·저장 방식과 FAQ를 확인할 수 있습니다. 분석 화면의 촬영 안내는 `/guide#photo-guide`로 연결하며, 예전 `/#guide` 북마크도 새 페이지로 이동합니다.

- FAQ는 질문과 답변을 브라우저 안에서 검색하며 사진이나 검색어를 서버로 보내거나 저장하지 않습니다. 주제 필터, 일치 항목 수, 검색 결과 없음, 전체 펼치기·접기와 검색 초기화를 제공합니다.
- `/guide#faq-history` 같은 질문 주소는 해당 답변을 펼쳐 보여 줍니다. 페이지 목차는 데스크톱에서 본문 패널 안의 읽는 위치를, 작은 화면에서는 페이지의 읽는 위치를 표시합니다. 좁은 화면에서는 목차를 본문 위에 배치합니다.
- 촬영·분석·편집은 각 기능 페이지에서 실행합니다. 안내 페이지를 열거나 검색하는 동작으로 사진을 선택하거나 AI를 호출하지 않습니다.

## 웹소켓 기능

화면 구성은 유지하고 로그인한 계정의 실시간 알림 연결을 추가했습니다. 기존 Flask·Waitress HTTP 서버는 그대로 사용하며, [websockets의 스레드 서버](https://websockets.readthedocs.io/en/stable/reference/sync/server.html)를 같은 프로세스의 별도 로컬 포트에서 실행합니다. 기존과 같이 `python app.py`로 두 서버를 함께 시작합니다.

- HTTP: `http://127.0.0.1:8000`
- WebSocket: `ws://127.0.0.1:8001/ws` (기본값)
- 설정 조회: 로그인 후 `GET /api/realtime` → `enabled`, `port`, `path`
- 설정: `.env`의 `ENABLE_WEBSOCKET=false`로 끌 수 있고 `WEBSOCKET_PORT`로 포트를 바꿀 수 있습니다. 포트 미지정 시 HTTP 포트 다음 번호를 사용합니다. HTTP와 웹소켓은 서로 다른 포트를 사용합니다.

메인·사진 분석·학습·학습 가이드·내 정보 페이지는 로그인 확인 후 자동 연결합니다. 별도 버튼·채팅 입력·화면 알림은 추가하지 않았습니다. 서버 시작 방법을 바꾸어 `create_app()`만 호출하면 웹소켓 리스너는 자동 시작하지 않습니다. 이 경우 필요할 때 `app.extensions["realtime"].start()`와 종료 시 `stop()`을 호출합니다.

### 연결과 메시지

기존 로그인 세션 쿠키를 사용합니다. 접속 페이지와 호스트 이름이 같은 `127.0.0.1` 또는 `localhost` 주소로 연결하며, `Origin`은 해당 HTTP 서버 주소와 일치해야 합니다. 세션·인증키를 URL에 넣지 않습니다. 비로그인·잘못된 쿠키·외부 Origin은 연결을 거부하고, 로그아웃·세션 만료·다시 로그인할 때 이전 세션 연결을 닫습니다.

| 방향 | JSON 메시지 | 역할 |
| --- | --- | --- |
| 서버 → 클라이언트 | `{"type":"connected","version":1}` | 연결 완료 |
| 클라이언트 → 서버 | `{"type":"ping"}` | 연결 확인 요청 |
| 서버 → 클라이언트 | `{"type":"pong"}` | 연결 확인 응답 |
| 클라이언트 → 서버 | `{"type":"subscribe","topics":["history","training"]}` | 내 계정의 기록·학습 변경 구독 |
| 서버 → 클라이언트 | `{"type":"subscribed","topics":["history","training"]}` | 구독 확인 |
| 서버 → 클라이언트 | `{"type":"history.updated"}` / `{"type":"training.updated"}` | 해당 계정의 변경 알림 |
| 클라이언트 → 서버 | `{"type":"status"}` | 내 계정 현황 요청 |
| 서버 → 클라이언트 | `{"type":"status","history_count":0,"training_count":0,"model_ready":false}` | 실제 계정 현황. 수치는 예시 |

리포트 저장·삭제, 학습 사진 추가·삭제와 분류기 학습이 성공하면 구독한 같은 계정의 연결에 변경 알림을 보냅니다. 사진·분석 본문·OCR 텍스트·익명 그룹 코드는 웹소켓에 넣지 않습니다. 사용자 ID를 보내 다른 계정을 구독하거나 웹소켓으로 데이터를 변경하는 명령은 지원하지 않습니다. 빈 `topics` 배열을 보내면 변경 알림 구독을 해제합니다.

### 브라우저에서 사용

`static/realtime.js`는 `window.HairlineRealtime`을 제공합니다. `connected`로 연결 상태를 확인하고, `ping()`·`requestStatus()`를 호출하거나 `connect()`·`disconnect()`로 직접 연결을 제어할 수 있습니다. 수신 내용은 `realtime-message`, 연결 상태는 `realtime-state` 문서 이벤트로 전달합니다. 화면 변경이 필요하면 해당 이벤트에서 기존 HTTP API를 다시 조회하도록 연결할 수 있습니다.

클라이언트는 25초마다 연결 확인 메시지를 보내고, 비정상 연결 종료 시 1·2·4·8·16초 간격으로 최대 5회 재연결합니다. 이후에는 새로고침이나 `connect()` 호출이 필요합니다. 비로그인·세션 종료·기능 비활성화 시 자동 재연결하지 않습니다. 로그아웃·계정 변경·페이지 종료 시 이전 연결과 타이머를 정리하고 늦게 도착한 이전 계정의 응답을 폐기합니다.

서버는 수신 메시지를 4KB·연결별 분당 60건, 연결 수를 계정별 4개·전체 32개, 연결별 알림 대기열을 32개로 제한합니다. HTTP 요청은 알림을 대기열에 넣는 즉시 완료하며 소켓 전송을 기다리지 않습니다. 이 구조는 현재 로컬 단일 프로세스용이며 여러 서버 인스턴스 간 알림 공유는 포함하지 않습니다.

## 오른쪽 헤어라인 도우미

상단 메뉴의 **사진 분석·변화 미리보기·로컬 학습·이용 안내**는 각각 별도 페이지로 이동하며 현재 페이지를 표시합니다. 이용 안내 안의 목차는 본문 스크롤 위치에 따라 활성 항목이 바뀝니다.

헤어라인 도우미는 **메인 페이지(`/`)에서만** 사용할 수 있습니다. 정해진 질문과 답변을 선택하는 챗봇이며 모든 화면 크기에서 우측 하단의 **헤어라인 도우미** 버튼으로 엽니다. 펼친 창도 최대 높이 560px로 하단에 배치합니다. 서브 페이지에는 도우미 버튼·창과 전용 JS/CSS를 포함하지 않습니다.

헤더의 **−** 버튼은 현재 대화를 우측 하단의 최소화 바에 접어 둡니다. 진행 중인 문항이나 결과 상태를 표시하며 누르면 이어서 열립니다. **×** 버튼은 기본 도우미 버튼 상태로 닫습니다. 두 동작 모두 현재 페이지의 응답을 유지하며, 계정 변경·처음으로·새로고침 시에는 초기화됩니다.

- **탈모 진행 상태 안내:** 헤어라인·가르마·정수리 변화, 갑작스러운 빠짐·두피 불편감, 사진 촬영과 상담 시점을 안내합니다.
- **자가 테스트:** 5문항에 ‘네·아니요·잘 모르겠어요’로 답하면 응답 요약과 준비된 후속 안내를 표시합니다. 이전 문항으로 돌아가거나 마지막 답변 수정·처음부터 다시 시작할 수 있습니다. 진단 점수·탈모 확률·진행 단계는 제공하지 않습니다.
- 외부 AI/API 호출, 자유 입력, 사진 전송 없이 브라우저에서 동작합니다. 응답을 DB나 브라우저 저장소에 보관하지 않으며, 새로고침·처음으로·계정 변경 시 초기화합니다.
- 안내는 [미국피부과학회 증상 안내](https://www.aad.org/public/diseases/hair-loss/insider/begin), [진단 안내](https://www.aad.org/public/diseases/hair-loss/treatment/diagnosis-treat), [NHS 안내](https://www.nhs.uk/symptoms/hair-loss/)를 참고해 작성했습니다. 자가 점검은 임상적으로 검증된 진단 설문이 아닙니다.

## 카메라·로그인·내 기록

로그인 후 상단의 **사용자 이름**을 누르면 별도 **내 정보** 페이지(`/profile`)로 이동합니다. 아이디·가입일, 전체 저장 리포트 수, 학습 사진 수, 로컬 모델 상태와 최근 리포트 저장일을 확인하고 내 기록·학습 관리로 이동할 수 있습니다. 비로그인 상태에서는 로그인 후 이 페이지로 돌아오며, 본인 계정의 정보만 표시합니다.

1. 상단 **회원가입**을 누르면 별도 `/register` 페이지에서 계정을 만들 수 있습니다. 기존 계정은 **로그인**을 눌러 `/login` 페이지로 이동합니다. 아이디는 한글·영문·숫자·밑줄 3~24자, 비밀번호는 8~128자입니다. 가입·로그인에 성공하면 분석 화면으로 돌아옵니다. 이메일이나 외부 로그인 서비스는 필요하지 않습니다.
2. 사진 분석·변화 미리보기·로컬 학습에서 **카메라로 촬영**을 누르고 브라우저 카메라 권한을 허용합니다. 전·후면을 전환할 수 있으며, **촬영하고 불러오기**를 누르면 해당 화면에 사진을 불러옵니다. 로컬 학습에서는 로그인 후 촬영하며 사진 미리보기·라벨·익명 그룹·저장 동의를 확인하고 **선택한 사진 등록하기**를 눌러야 저장됩니다. 카메라가 없다면 파일 업로드를 사용하세요.
3. 사진 분석에서는 사진을 확인하고 Google 전송 동의 후 분석합니다. 카메라 화면은 실시간으로 서버에 전송하지 않으며 음성은 수집하지 않습니다. 창을 닫거나 탭을 숨기면 카메라를 해제합니다.
4. 로그인한 상태에서 **분석 리포트를 내 계정에 저장**을 선택하면 결과가 DB에 저장됩니다. **이 사진도 내 계정에 함께 저장해요**도 선택하면 촬영 메타데이터를 제거한 사진과 크기·형식·용량·해시·관찰 부위를 계정별 DB에 함께 저장합니다. 상단 **내 기록**에서 최근 50개 리포트와 함께 저장한 사진을 다시 열거나 개별 삭제할 수 있습니다. 이 목록 제한은 전체 저장 개수 제한이 아닙니다.
5. **로컬 학습**의 사진·모델도 로그인한 계정별로 관리됩니다. 로그아웃하거나 계정을 바꾸면 사진 미리보기·리포트·학습 목록을 화면에서 지우고 진행 중인 브라우저 요청을 중단합니다.

로그인 없이도 일반 사진 분석·영역 추출·합성을 이용할 수 있습니다. 로컬 학습·분류와 기록 저장은 로그인이 필요합니다. 로컬 분류기 학습은 별도 페이지 **http://127.0.0.1:8000/training** 에서 하고, 학습한 모델은 사진 분석 페이지의 "로컬 모델로 분류"에서 사용합니다. 카메라는 `http://127.0.0.1:8000` 또는 `localhost`에서 사용하세요. 전면 미리보기만 좌우 반전하며 촬영 파일은 원래 방향입니다. 실물 카메라 권한·장치 동작은 사용 환경에서 확인해야 합니다.

SQLite는 Python 기본 모듈을 사용하므로 별도 DB 서버나 패키지를 설치할 필요가 없습니다. 첫 실행에 다음 로컬 파일을 만듭니다.

| 위치 | 보관 내용 |
| --- | --- |
| `data/hairline.sqlite3` | `users`: 아이디·scrypt 비밀번호 해시, `sessions`: 세션 토큰 해시·만료, `analysis_history`: 관찰 리포트, `photos`: 계정별 JPEG BLOB·사진 정보·학습 라벨/정답 |
| `data/.session_secret` | 서명 키 자동 생성·재사용 (`APP_SECRET_KEY` 미지정 시) |
| `data/training/users/<계정 ID>/` | 저장 동의 후 등록한 학습 사진·특징값·라벨·모델 |

사진 저장은 기본 꺼짐이며 별도 선택한 분석 사진과 학습 저장에 동의한 사진을 SQLite에 보관합니다. 사진 원본의 파일명·EXIF/GPS와 입력 OCR 원문은 저장하지 않습니다. 기존 리포트에 없던 사진을 소급해서 만들지는 않습니다. 기존 계정별 학습 사진은 시작 시 DB에 중복 없이 등록하며, 기존 JSON·JPEG·모델은 학습 작업 호환성을 위해 보존합니다. DB·서명 키·학습 폴더는 Git 및 웹 정적 제공에서 제외했습니다. 이전 공용 `data/training/` 데이터를 계정에 자동 귀속시키지 않습니다. 저장 구조·API·백업 범위는 [계정과 사진 DB](docs/계정_사진_DB.md)에 정리했습니다.

세션은 최대 8시간이며 서버 DB에서도 검증하고 로그아웃 시 폐기합니다. 쿠키는 HttpOnly·SameSite=Lax, 변경 요청은 CSRF 토큰을 확인합니다. 현재는 로컬 HTTP 실행용이며 비밀번호 재설정·이메일 인증·인터넷 공개 배포는 구현 범위에 포함하지 않습니다. 선택 설정은 `.env.example`의 `DATABASE_PATH`와 `APP_SECRET_KEY`를 참고하세요. 기존 `.env` 키를 변경할 필요는 없습니다.

## 학습 횟수 가이드

**http://127.0.0.1:8000/training-guide** 에서 학습 횟수·최소 사진 수·사람 그룹 예시·재학습 시점을 확인합니다. 분석 화면의 학습 등록 영역과 이용 안내에서도 연결됩니다. 설명은 로그인 없이 읽을 수 있으며, 로그인하면 실제 계정의 사진·사람 그룹 수와 모델 준비 상태를 표시합니다. 로컬 학습 화면은 상단 소개·가이드 카드·로그인 안내 없이 학습 작업 카드부터 시작합니다.

현재 SVM은 조건을 갖춘 데이터로 한 번 학습하고, 데이터를 추가·삭제한 뒤 다시 한 번 학습합니다. 같은 데이터에 학습 횟수가 누적되는 방식이 아닙니다. 자동 학습이 이미 완료됐다면 같은 데이터로 다시 누를 필요가 없습니다. 최소 조건은 라벨별 5장·각 라벨의 사람 그룹 2개 이상·전체 4개 그룹이며, 최소 사진 수는 총 10장입니다. 이 조건은 의료적 정확도를 보장하는 표본 수가 아닙니다.

## 분석 화면의 사진을 학습에 저장

1. 로그인 후 **내 헤어라인 살펴보기**에서 카메라로 촬영하거나 사진을 선택합니다.
2. **이 사진으로 로컬 학습하기**를 펼치고 사진 라벨과 익명 사람 그룹(예: `p001`)을 입력합니다. 같은 사람은 같은 코드를 사용합니다. 사진을 바꾸면 라벨과 자동 저장 선택은 초기화됩니다.
3. **이 사진을 학습용으로 저장**을 누르면 Google 전송 없이 바로 등록합니다. 또는 **AI 분석 후 이 사진을 학습용으로 저장**을 선택해 분석 요청이 끝난 뒤 등록할 수 있습니다. Gemini 할당량·연결 오류가 나더라도 선택한 로컬 저장은 시도합니다. 페이지를 닫으면 브라우저에서 대기 중인 작업은 이어서 실행되지 않습니다.
4. 저장 위치는 `data/training/users/<계정 ID>/학습/<익명 ID>.jpg`입니다. 첫 저장 시 폴더를 생성하고, 촬영 메타데이터를 제거한 JPEG와 라벨·그룹·특징값을 기존 학습 목록에 등록합니다. 학습 페이지에서 직접 등록한 기존 사진은 계속 `photos/`에 보관합니다.
5. **데이터가 충분하면 저장 후 분류기도 학습**이 선택되어 있으면, 라벨별 최소 5장·각 라벨의 사람 그룹 2개 이상·전체 4개 그룹을 충족한 경우 저장 후 로컬 SVM을 학습합니다. 사진 한 장이나 한 사람의 사진만으로 학습 조건이 충족되지는 않습니다. 조건이 부족하면 사진 등록까지만 완료하고 필요한 데이터를 안내합니다.

분석 후 자동 저장은 현재 사진의 Gemini 관찰·로컬 분류 요청이 끝난 후 실행합니다. 사진 저장은 성공했으나 모델 학습에 실패한 경우 사진을 보존하고 재학습 안내를 표시합니다. 중복 사진은 추가하지 않으며, 저장된 사진은 **로컬 학습 → 등록한 사진 목록**에서 출처를 확인하고 삭제할 수 있습니다. 이 사진들은 기존 학습 폴더와 함께 Git에서 제외되고 웹 정적 파일로 제공되지 않습니다.

## API 키 설정

루트의 `.env`에 다음 값을 입력하고 서버를 다시 실행하세요. 키를 HTML이나 JavaScript에 넣지 않습니다.

```dotenv
GEMINI_API_KEY=발급받은_키
GEMINI_ANALYSIS_MODEL=gemini-2.5-flash
```

- 키 발급: [Google AI Studio](https://aistudio.google.com/apikey)
- `.env`와 로컬 모델·가상환경은 `.gitignore`로 제외했습니다.
- `.env.example`은 변수 이름과 기본값을 공유하기 위한 파일입니다.
- 키가 없어도 사진 미리보기, MediaPipe 영역 추출과 OpenCV 합성을 이용할 수 있습니다.
- 모델의 실제 사용 가능 여부와 무료 할당량은 계정·지역·시점에 따라 달라집니다. 모델 변경은 `.env`에서 할 수 있습니다.

### AI 연결 오류 확인

‘AI 서비스에 연결할 수 없어요’는 서버에서 Google로 보내는 HTTPS 요청이 실패할 때 표시합니다. 외부 통신이 제한된 자동화 환경에서 서버를 시작한 경우에도 발생할 수 있습니다. 서버를 재시작할 때는 외부 네트워크에 접근할 수 있는 일반 실행 환경에서 위의 실행 명령을 사용하세요.

`/api/status`의 `analysis_ready`는 키 설정 여부를 표시합니다. 실제 통신·키·모델 접근은 사진을 보내지 않는 [Google 공식 모델 정보 조회](https://ai.google.dev/api/models#method:-models.get)로 별도 확인할 수 있습니다. 키는 서버 안에서 `x-goog-api-key` 헤더로 사용하고 진단 출력·URL·화면에는 포함하지 않습니다.

Gemini의 일시적인 HTTP 500·502·503·504 응답은 사진 분석에 한해 최대 2회 추가 시도합니다. 기본 대기 간격은 1초·2초이며 `Retry-After`와 남은 요청 대기 시간을 확인합니다. 키·권한·할당량·모델·잘못된 요청, 연결 오류·타임아웃은 자동 반복하지 않습니다. 유료 이미지 생성도 자동으로 다시 요청하지 않습니다. 계속 실패하면 일시적인 서비스 오류, 잘못된 요청 설정, 프로젝트 이용 조건 등을 구분해 안내합니다. 서버에는 HTTP 상태와 시도 횟수만 기록하며 Google 오류 본문·키·사진은 남기지 않습니다. [Google 오류 해결 안내](https://ai.google.dev/gemini-api/docs/troubleshooting)

### Gemini 한도 시 로컬 Ollama 전환

사진 분석에서 Gemini가 **HTTP 429 한도 오류**를 반환하면 같은 사진·관찰 설정을 이 컴퓨터의 Ollama 비전 모델로 이어서 처리합니다. 실제 사용 모델과 로컬 전환 여부를 리포트에 표시합니다. 키·권한·네트워크 오류나 유료 이미지 편집은 자동 전환하지 않습니다.

Ollama를 실행하고 아래 비전 모델을 한 번 준비하세요. 텍스트 전용 `qwen2.5` 모델은 사진 분석에 사용할 수 없습니다.

```powershell
ollama pull qwen2.5vl:3b
```

기본값은 `ENABLE_OLLAMA_FALLBACK=true`, `OLLAMA_BASE_URL=http://127.0.0.1:11434`, `OLLAMA_ANALYSIS_MODEL=qwen2.5vl:3b`, `OLLAMA_API_TIMEOUT=120`입니다. `.env`에서 변경 후 앱 서버를 재시작할 수 있습니다. 모델 미설치·연결 실패·텍스트 전용·불완전 결과를 구분하며 자동 다운로드나 사진 저장은 하지 않습니다. 전환 전 Google 전송 동의는 계속 필요합니다. 요청 범위·개인정보·대기·설정·검증은 [Ollama 자동 전환](docs/Ollama_자동전환.md)에 정리했습니다.

### Qwen 비전 모델 학습

**http://127.0.0.1:8000/training/vision** 에서 로그인해 사진과 직접 확인한 관찰 정답을 저장하고 실제 QLoRA 학습을 실행할 수 있습니다. 로컬 학습(`/training`) 화면은 사진 분류기 학습에 집중하며 비전 학습 이동 버튼을 표시하지 않습니다. 기존 HOG·SVM 분류기와 별개이며 같은 Qwen 기본 가중치를 4비트로 불러와 LoRA를 학습합니다. Ollama의 압축 모델을 직접 재학습하거나 기존 모델을 덮어쓰지 않습니다.

관찰 가능·불가 예시 각각 4장 이상, 익명 그룹 4개 이상을 준비하고 학습 시작을 누릅니다. 그룹을 분리한 검증 손실·진행 단계·취소, 선택 사진 테스트·어댑터 ZIP 저장을 제공합니다. 완료 모델에서 **내 분석에 적용**을 누르면 본인 계정의 Gemini 한도 발생 시 학습 모델을 로컬 프로세스로 사용합니다. 적용 해제 시 기존 Ollama로 돌아갑니다. 실제 사용자 사진의 학습과 적용은 자동 실행하지 않습니다.

학습 환경은 웹앱과 분리된 `.venv-vlm`이며 다음 명령으로 설치할 수 있습니다. NVIDIA CUDA GPU가 필요합니다.

```powershell
powershell -File scripts/setup_vlm.ps1
```

저장·계정 경계·학습 설정·실제 확인 범위는 [비전 모델 학습](docs/비전_모델_학습.md)에 정리했습니다. 현재 환경에는 학습용 가중치와 CUDA 패키지를 준비했습니다.

```powershell
.\.venv\Scripts\python.exe app.py
```

기존 `.env`는 덮어쓰지 마세요. Python 3.12가 이미 설치되어 있다면 일반 `venv`와 `pip`로 같은 패키지를 설치할 수도 있습니다. 정확한 검증 환경은 `requirements-lock.txt`에 기록합니다.

## 선택 사항: 로컬 OCR API

문자 추출 메뉴·섹션과 사진 분석의 OCR 보조 입력은 화면에서 제거했습니다. 기존 `/api/ocr` 백엔드와 설치 도구는 개발용으로 유지하며, 아래 내용은 API를 직접 사용할 때의 안내입니다.

- 지원: JPG·PNG·WEBP 이미지 속 한국어·영어·숫자. PDF 입력과 표 구조 복원은 포함하지 않습니다.
- 기존과 같은 10MB·20MP 제한을 적용하고, 작은 글자를 보존하기 위해 OCR만 최대 2560px로 처리합니다.
- OCR API만 실행할 때는 이미지와 추출 결과를 외부 API로 전송하지 않습니다. 결과 자체는 파일·DB에 자동 저장하지 않습니다.
- 글자가 없으면 빈 결과를 안내합니다. 인식 결과는 원본과 대조해야 하며, 추출한 검사 수치를 자동으로 의학적으로 해석하지 않습니다.
- 이 작업 환경에는 CPU용 패키지와 경량 모델 두 개를 설치했습니다.

새 환경에서는 기존 Python 3.12 가상환경에 다음을 추가합니다.

```powershell
uv pip install --python .\.venv\Scripts\python.exe -r requirements-ocr.txt
.\.venv\Scripts\python.exe setup_ocr.py
.\.venv\Scripts\python.exe app.py
```

엔진은 PaddleOCR 3.3.2·PaddlePaddle 3.2.0, 모델은 `PP-OCRv5_mobile_det`와 `korean_PP-OCRv5_mobile_rec`입니다. Windows 호환성을 위해 `chardet`·`pandas`도 확인한 버전으로 고정했습니다. 정확한 설치 환경은 `requirements-ocr-lock.txt`에 있습니다. PaddlePaddle은 첫 초기화 때 사용자 홈에 빈 데이터셋 캐시 폴더를 만들 수 있습니다.

`POST /api/ocr`는 `photo` 필드로 이미지를 받아 `text`, `lines`(글자·모델 신뢰도·좌표), `line_count`, `elapsed_ms`를 반환합니다. 모델 신뢰도는 인식 정답률이나 의료적 정확도가 아닙니다. [PaddleOCR 공식 안내](https://www.paddleocr.ai/latest/en/quick_start.html)

## 로컬 사진 학습과 Gemini 보조

**로컬 사진 학습은 사용자 라벨 분류**를 담당합니다. Gemini 모델의 가중치를 재학습하는 기능은 아닙니다.

1. **로컬 학습**에서 파일을 선택하거나 카메라로 촬영한 뒤 `기준 사진` / `탈모 의심 사진` 라벨과 익명 그룹 코드(예: `p001`)를 정합니다. 촬영한 사진은 미리보기만 제공하며 직접 등록하기 전에는 서버에 보내거나 저장하지 않습니다. 파일을 새로 선택하면 촬영 사진을, 새로 촬영하면 파일 선택을 초기화해 함께 등록되지 않도록 합니다. 같은 사람의 사진은 반드시 같은 코드를 사용합니다. 정면과 정수리 등 다른 구도는 섞지 않는 것을 권합니다.
2. 저장 동의 후 등록합니다. 최소 각 라벨 5장, 각 라벨 2개 그룹, 전체 4개 그룹을 준비합니다. 이는 실행을 위한 최소 조건이며 진단 정확도를 보장하는 표본 수가 아닙니다.
3. **로컬 분류기 학습하기**를 누릅니다. OpenCV HOG·색상·명암 특징과 선형 SVM으로 CPU에서 학습합니다. 별도의 GPU나 외부 API는 사용하지 않습니다.
4. 분석 영역의 **로컬 모델로 분류**로 확인합니다. **학습된 로컬 분류 결과를 Gemini에 함께 전송**을 선택하면 현재 사진의 분류 라벨만 보조 자료로 함께 보냅니다. 학습용 원본 사진·특징값·그룹 코드는 Google에 보내지 않습니다.

학습·검증 사진은 사람 그룹으로 분리하며, 같은 사진과 매우 유사한 사진의 중복 등록을 막습니다. 검증에 쓰는 사진으로 모델을 다시 학습하지 않고, 검증 점수에 따라 분할을 고르지도 않습니다. 내부 검증의 **사용자 라벨 일치율**, 검증 표본 수, 다수 라벨 기준선을 표시합니다. 이는 임상적 탈모 진단 정확도가 아닙니다.

사진을 추가·삭제하면 기존 모델을 사용하지 않고 재학습을 요구합니다. 사용자가 라벨을 잘못 붙이거나 같은 사람을 여러 그룹으로 나누면 결과가 왜곡될 수 있습니다. 단순 특징 기반 분류기는 조명·배경·촬영 구도도 학습할 수 있습니다. 신뢰할 만한 진단 모델로 사용하려면 별도의 데이터 설계와 외부 검증이 필요합니다.

학습 작업용 파일은 `data/training/users/<계정 ID>/`에 두며 사진 JPEG·라벨·그룹·특징값은 SQLite의 계정별 `photos`에도 저장합니다. SVM XML과 평가 메타데이터는 기존 학습 폴더에 보관합니다. 학습 사진을 삭제하면 DB에서도 삭제하며, 저장 실패 시 DB·목록·사진을 되돌립니다. Git에서 제외했고 웹 정적 파일로 제공하지 않습니다. 저장된 모델은 이 앱이 만든 모델만 사용하며 외부 pickle 모델 업로드는 지원하지 않습니다. 새 두피 이미지 자료의 중복·등급 불균형·촬영 방식과 기존 학습 기능의 호환성은 [데이터셋 검토 보고서](docs/탈모_데이터셋_검토_2026-11-02.md)에 정리했습니다.

학습 API: `GET /api/training/status`, `POST /api/training/add`(`photo`, `label`, `group`, `storage_consent=true`, 선택 `source=analysis`, `train_if_ready=true`), `POST /api/training/train`, `POST /api/training/remove`(`id`), `POST /api/classify`(`photo`). 등록 응답의 `auto_training`은 `not_requested`·`needs_data`·`completed`·`failed` 상태를 구분합니다. 기존 `/api/analyze`는 `ocr_text`·`ocr_text_consent`·`share_local_result`와 아래의 `scalp_macro`를 선택적으로 받습니다.

## Gemini·Ollama 공통 확대 두피 참고 모델

2026-11-02 수령 이미지 18,513장에서 완전 중복을 제거한 **16,298장**으로 별도 MobileNetV3 Small을 학습했습니다. 학습 11,047장·검증 2,891장·테스트 2,360장이며, 6회 학습 중 검증 macro-F1이 가장 높았던 4회차를 적용했습니다. 내부 테스트의 균형 정확도는 **61.2%**, macro-F1은 **0.520**입니다. 일반 이마 사진이나 임상 진단 정확도를 나타내지 않습니다.

사진 분석의 **추가 옵션 → 로컬 분류 보조 자료 → 확대 두피 사진의 학습 분류 결과를 AI에 함께 전달해요**를 선택하면 같은 사진을 로컬에서 한 번 분류하고 그 결과를 Gemini에 전달합니다. Gemini 한도 오류 때는 동일한 결과가 Ollama 백업에도 전달됩니다. 일반 사진에는 기본 적용하지 않으며, 새 사진을 고르면 선택이 해제됩니다. 불확실한 결과는 등급 표시를 보류합니다.

웹 모델은 `models/scalp-classifier/model.onnx`와 `metadata.json`입니다. 웹에서는 기존 OpenCV CPU 런타임을 사용하고 학습은 별도 `.venv-vlm`에서 실행합니다. `GET /api/status`의 `scalp_reference.ready`로 준비 상태를 확인하며 `POST /api/analyze`에 `scalp_macro=true`로 선택합니다. 결과의 `scalp_reference`는 화면·텍스트/JSON 내보내기·선택한 기록 저장에 포함됩니다. 원본 자료와 모델 파일은 Git·웹 정적 파일에서 제외했습니다.

재현 명령, 클래스별 성능, 데이터 분할의 한계와 실제 연결 검증은 [공통 두피 학습 모델](docs/공통_두피_학습_모델.md)에 있습니다. Gemini·Ollama 생성 모델 자체의 가중치를 미세조정한 작업은 아닙니다.

약·치료제 안내에는 식약처 허가정보로 확인한 **의약품 20종·제조/수입사 13곳**의 목록도 제공합니다. 바르는 미녹시딜·알파트라디올, 먹는 피나스테리드·두타스테리드, 복합성분 보조치료 의약품의 5종류로 나누며 종류별/제조·수입사별 묶음, 종류·업체 필터, 제품 검색을 함께 사용할 수 있습니다. 제품별 성분·함량·제형·일반/전문 구분과 공식 원문 링크를 표시합니다. 업체는 품목허가 업체 기준이며 위탁 제조사는 따로 표시합니다. [전체 목록·확인 출처](docs/탈모_의약품_목록.md)에 정리했습니다.

| PaddleOCR | 개발용 API의 한국어·영어·숫자 추출 · 화면 미제공 | 로컬 CPU 실행. API 키·외부 전송 없이 사용 |
| Stable Diffusion Inpainting | 편집 마스크 안의 로컬 AI 인페인팅 | 선택 기능. CUDA GPU·별도 패키지·호환 로컬 모델 필요 |
| Gemini 이미지 생성 API | 원본 사진을 바탕으로 한 가상 모발 편집 | 선택 유료 기능. 서버 설정과 매 요청의 유료 동의 필요 |

무료 분석 할당량이 이미지 생성까지 무료라는 뜻은 아닙니다. 이미지 생성 모델 ID는 사용 가능한 모델을 확인한 뒤 별도로 설정합니다. 중단된 `gemini-2.5-flash-image`를 기본값으로 사용하지 않습니다. [Gemini 공식 요금](https://ai.google.dev/gemini-api/docs/pricing)

## 로컬 Stable Diffusion 활성화

기본 설치에는 용량이 큰 PyTorch·모델 가중치를 포함하지 않았습니다. 먼저 GPU에 맞는 [CUDA 지원 PyTorch](https://pytorch.org/get-started/locally/)를 설치하고, 해당 가상환경에 추가 의존성을 설치합니다.

```powershell
uv pip install --python .\.venv\Scripts\python.exe -r requirements-inpainting.txt
```

Diffusers 형식의 **인페인팅용** 모델을 사용 조건에 맞게 로컬에 준비하고 `.env`를 수정합니다.

```dotenv
ENABLE_SD_INPAINTING=true
SD_MODEL_PATH=C:/models/내가_준비한_인페인팅_모델
```

앱은 로컬 파일만 읽으며 가중치를 자동 다운로드하지 않습니다. safetensors 모델을 사용하고 CUDA GPU가 없으면 실행을 거부합니다. GPU 메모리 사용을 줄이기 위해 최대 512px 범위에서 처리하며, 결과를 원본 크기로 돌린 뒤 편집 영역 밖은 원본을 유지합니다. 실제 생성 속도와 품질은 모델·GPU·사진에 따라 달라집니다. [Diffusers 인페인팅 문서](https://huggingface.co/docs/diffusers/en/using-diffusers/inpaint)

## Gemini 유료 이미지 생성 활성화

사용 가능한 이미지 편집 모델과 요금을 확인한 뒤 설정합니다.

```dotenv
ENABLE_PAID_IMAGE_GENERATION=true
GEMINI_IMAGE_MODEL=사용_가능한_이미지_생성_모델_ID
```

서버를 재시작하면 선택 메뉴에 활성화됩니다. 사진 전송 동의와 유료 호출 확인을 모두 체크해야 실행됩니다. 분석 실패를 유료 생성으로 자동 대체하거나 자동 재시도하지 않습니다.

## 개인정보와 결과의 의미

- 일반 분석·OCR 사진은 자동 저장하지 않습니다. 분석 사진은 리포트 저장과 사진 저장을 함께 선택한 경우에만 SQLite에 보관합니다. 학습 등록에 동의한 사진·라벨·특징값은 계정별 SQLite와 학습 폴더에 저장합니다. 로그아웃·계정 변경 시 화면의 개인 데이터를 정리합니다.
- 업로드는 JPG/PNG/WEBP, 최대 10MB, 최대 20MP, 가로·세로 각각 160px 이상입니다. EXIF 방향을 적용하고 위치 등 메타데이터를 제거합니다. 사진 분석은 최대 2048px, 문자 OCR은 최대 2560px, 나머지 기본 처리는 최대 1280px이며 로컬 비전 추론의 사진 입력은 1280px로 제한합니다.
- OCR·영역 추출·로컬 학습·분류·OpenCV·로컬 인페인팅은 컴퓨터 안에서 실행됩니다. Gemini 분석·생성을 요청할 때 사진과 별도로 전송을 선택한 보조 자료를 Google에 전송합니다. Google의 별도 보관·데이터 이용 조건이 적용됩니다. 특히 무료 API의 데이터 이용 조건을 확인하세요. [API 이용 조건](https://ai.google.dev/gemini-api/terms)
- 모발 면적 비율은 **사진 전체에서 마스크가 차지하는 비율**입니다. 모발 밀도, 질환 확률 또는 탈모 비율이 아닙니다.
- 관찰 리포트는 확진, 중증도 등급, 모낭 수, 미래 진행 예측을 제공하지 않습니다. 같은 사진도 조명과 각도에 영향을 받습니다. 우려가 지속되면 피부과 상담을 권합니다. [피부과 전문의의 진단 안내](https://www.aad.org/public/diseases/hair-loss/treatment/diagnosis-treat)
- 편집 이미지는 가상의 외형 변화입니다. 다운로드 이미지에도 이 사실을 표시합니다.
- 서버는 `127.0.0.1`에만 바인딩합니다. 다른 출처의 브라우저 요청을 제한하고 `.env`·코드·모델 파일을 웹 경로로 제공하지 않습니다. 인터넷 공개 서버로 사용하려면 HTTPS·외부 접속 인증 정책·요청 제한·배포 설계를 별도로 검토해야 합니다.

## 검증과 지표

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check static/app.js
node --check static/training.js
node --check static/auth.js
node --check static/account-page.js
node --check static/camera.js
node --test tests/*.test.cjs
# Windows에서 생성한 한국어·영어 테스트 이미지로 실제 OCR 확인:
.\.venv\Scripts\python.exe scripts/verify_ocr.py
```

자동 검증은 입력·동의·외부 API 실패·로컬 합성·OCR·학습과 함께 비밀번호 해시, 세션 폐기·만료, CSRF, 계정 간 접근 차단, 리포트 저장 동의·삭제·DB 재시작 유지도 확인합니다. 카메라는 모의 미디어 장치로 권한 요청·촬영 파일 생성·해제·늦은 응답 폐기를 검증합니다. 실제 브라우저 렌더링과 실물 카메라 사용은 별도 확인이 필요합니다. 외부 API 테스트는 모의 응답을 사용하므로 비용이 발생하지 않으며, 실제 Gemini 성능 평가를 대신하지 않습니다.

영역 추출과 분석·합성 응답에 실제 처리 시간(`elapsed_ms`)을 포함합니다. 개발 지표로 같은 공개·동의된 평가 사진 집합의 응답 시간과 처리 오류율을 측정할 수 있습니다. 탈모 진단 정확도를 측정했다고 표현하지 않습니다. 테스트용 단순 합성 도형은 의료 성능 평가 자료로 사용하지 않습니다.

실제 Gemini 분석·유료 생성은 API 키가, 로컬 인페인팅은 모델·GPU가 있어야 별도 확인할 수 있습니다.
