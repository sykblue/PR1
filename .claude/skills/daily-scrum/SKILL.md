# 데일리 스크럼 자동 작성

인자로 날짜(`2026-11-02` 형식)를 받으면 그 날짜, 없으면 오늘 날짜로 쓴다.

## 1. 근거 모으기 (읽기만)

1. **형식 기준**: `데일리스크럼/`에서 가장 최근 파일 1~2개를 읽는다. 제목 형식, 섹션 순서, 말투를 그대로 따른다.
   - 이전 파일의 "📌 내일 할 일"을 오늘 한 일과 대조한다. 한 것은 "오늘 한 일"에 넣고, 못 한 것은 다음 할 일로 넘긴다.
2. **개발 기록**: `docs/개발 기록.md`에서 그 날짜에 해당하는 부분을 찾는다.
   - 제목 형식이 섞여 있다. `## YYYY-MM-DD: ...`, `### YYYY-MM-DD ...`, 그리고 날짜 없는 `###` 소제목이 있다. 날짜 없는 소제목은 바로 위 날짜 제목에 속한다.
   - 직전 스크럼을 쓴 시각 이후에 적힌 항목이 직전 날짜 제목 아래 있을 수 있다. 직전 스크럼 파일에 없는 항목이면 오늘 것으로 볼지 파일 수정 시각으로 판단한다.
3. **파일 수정 시각**: 그날 바뀐 파일을 확인한다. `.cache`, `.venv*`, `.uv-cache`, `__pycache__`, `models`, `data`는 뺀다.
   ```bash
   find . -type f -newermt "YYYY-MM-DD 00:00" ! -newermt "YYYY-MM-DD+1 00:00" -not -path './.cache/*' -not -path './.venv*' -not -path './.uv-cache/*' -not -path '*/__pycache__/*' -not -path './models/*' -not -path './data/*'
   ```
4. **테스트 수**: 개발 기록에 적힌 숫자를 쓴다. 기록에 없으면 직접 돌리지 말고 "기록 없음"으로 둔다.
5. **브라우저 확인 결과**: 그날 확인한 기록이 대화나 문서에 있으면 진행 상황에 넣는다.

## 2. 쓰기

파일: `데일리스크럼/YYYY-MM-DD_데일리스크럼.md`. 같은 이름의 파일이 이미 있으면 덮어쓰지 말고, 사용자에게 보완할지 먼저 묻는다.

```markdown
# MM/DD (요일) 데일리 스크럼 — Hairline Lab · N일차

> 오늘의 목표: **한 줄**

### ✅ 오늘 한 일
- **묶음 제목**
  - 구체 항목 (수치·파일명·경로는 `코드`로)

### 📊 진행 상황
- 자동 테스트 **Python N개 + Node N개 = N개 통과** (어제 N개)
- 실제로 확인한 동작과 수치

### 🚧 이슈와 해결
- 문제 → 해결
- **막힌 점**: 아직 못 한 것과 이유

### 📌 내일 할 일
- [ ] 항목
```

- N일차는 `데일리스크럼/`의 기존 파일 수 + 1이다.
- 요일은 한국어 한 글자(월·화·수·목·금·토·일)로 쓴다.
- 오늘의 목표는 그날 한 일을 한 문장으로 묶어 쓴다.

## 3. 노션에 올리기

노션은 포트폴리오형 프로젝트 개요 구조다. 홈 "Hairline Lab"(ID `409091bd305b80ed9d85d6360d63835e`)에 개요·기능·기술 스택·"프로젝트 보드" 데이터베이스가 있고, 아래에 소개·기능·데일리 스크럼·문서 페이지가 있다.

로컬 파일을 쓴 뒤 "📅 데일리 스크럼" 섹션 페이지(ID `40c091bd305b81f4bb6ef50e57ac89eb`) 아래에 하위 페이지로 올린다.

- 먼저 부모 페이지를 fetch해서 같은 제목의 하위 페이지가 이미 있는지 확인한다. 있으면 새로 만들지 않고, 그 페이지를 `replace_content`로 갱신할지 사용자에게 묻는다.
- 새 페이지 설정: 부모 `page_id`, 아이콘 `📅`, 제목은 로컬 파일의 `# ` 제목줄에서 `# `를 뺀 것이다.
- 본문은 로컬 파일에서 제목줄을 뺀 나머지를 그대로 넣는다. 인용·소제목·목록·`- [ ]` 할 일은 노션 마크다운에서도 그대로 쓸 수 있다.
- 노션 연결이 안 되면 로컬 파일만 쓰고 "노션 업로드 실패"를 알린다.
- 새 하위 페이지를 만든 뒤 아래를 정리한다.
  - **프로젝트 보드** (데이터 소스 `collection://1816c580-a524-42a0-bf66-c5eaf2c6515c`, 속성 `작업`·`상태`(할 일/진행 중/완료)·`분류`·`일차`·`날짜`): 먼저 `query_data_sources`로 기존 행을 읽는다. "오늘 한 일"의 굵은 묶음 제목마다 `완료` 행을 더한다(`일차`·`날짜` 채움). 그 일이 이미 `할 일`/`진행 중` 행으로 있으면 새로 만들지 말고 상태만 `완료`로 바꾼다. "내일 할 일" 중 보드에 없는 항목은 `할 일`로 더한다. `일차` 옵션에 새 일차가 없으면 `update_data_source`로 먼저 추가한다.
  - **데일리 스크럼 페이지**: 맨 끝에 붙은 새 `<page>` 태그를 "## 📅 전체 기록" 바로 아래, 목록 맨 위로 옮긴다. "🗓️ 진행 타임라인"에 새 일차 콜아웃(`N️⃣`, `MM/DD · 짧은 제목`, 그날의 목표)을 더하고 `blue_bg`와 "← 지금"을 새 일차로 옮긴다.
  - **홈**: 기간 줄의 "(지금 N일차)"를 바꾼다. **소개 페이지**: 프로젝트 정보 표의 "지금 N일차"를 바꾼다.
  - 문서 페이지 토글의 HTML embed(`hairline-lab-home.html`)는 고정 파일이라 자동으로 바뀌지 않는다. 갱신하려면 HTML을 고쳐 다시 올려야 하므로 사용자에게 먼저 묻는다.

## 규칙

- 기록에 있는 사실만 쓴다. 테스트 수, 시간, 수치를 만들어 내지 않는다.
- 개발 기록이 "검증하지 못했다"고 적은 것은 "막힌 점"에 그대로 옮긴다. 정적 검사나 모의 테스트를 실제 브라우저 확인처럼 쓰지 않는다.
- 진단, 정확도 개선처럼 기록보다 부풀린 표현을 쓰지 않는다.
- 그날 근거가 하나도 없으면 파일을 만들지 않고 "작업 기록이 없어요"라고 알린다.
- 다 쓰면 파일 경로와, 근거로 쓴 기록 항목을 짧게 알려 준다.
